How to use this sheet

Read order, legend and exam-day checklist

One read of each subject covers every question in the 2022/2023 bank plus the syllabus topics the bank skipped. Each subject is about 10 minutes; the whole sheet is one evening.

  • Bold = the exact word or number the MCQ hinges on.
  • "Bank key:" = the answer the question bank marks when it differs from the textbook. In the exam, match the bank key; the full list is in the last section.
  • Formulas and worked numbers are the ones the bank reuses; learn the pattern, not just the answer.

Exam-day checklist (100 MCQs, 8 subjects, about 12 each):

  • Night before: read the last section (bank-key traps) and every subject's formulas.
  • In the hall: first pass answers every question you know in under 30 seconds; second pass does the numericals.
  • Numericals: draw the Gantt chart, closure, precedence graph or K-map on rough paper; never do them in your head.
  • "All of the above" is the bank's answer far more often than chance when every option is individually true.

Digital Logic & Computer Organization

Boolean algebra and K-maps • Combinational circuits (no memory) • Sequential circuits (flip-flops, counters) • Data representation • CPU, memory transfer and control unit • Instructions and addressing modes • Pipelining • Memory hierarchy, cache, virtual memory • I/O, DMA, interrupts, RAID

Boolean algebra and K-maps

  • n variables → 2ⁿ minterms (2 vars → 4, 3 → 8, 4 → 16). Minterm m5 of (A,B,C) = 101 = AB'C.
  • Absorption: A + AB = A, A(A + B) = A; A + A'B = A + B. So X + XY' + XY'Z = X → zero gates ("None of the options").
  • De Morgan: (A + B)' = A'B', (AB)' = A' + B'. NAND and NOR are universal.
  • K-map cells are labelled in Gray code (00, 01, 11, 10). Groups are powers of 2; a group of 2ᵏ removes k variables. Don't-cares are used only if they help.
  • Tabulation (Quine–McCluskey) starts from the minterms written as numbers. Bank key: "List of integers". Group by the number of 1s.

Combinational circuits (no memory)

  • Half adder: Sum = A ⊕ B, Carry = AB. Full adder = 2 half adders + 1 OR; Sum = A ⊕ B ⊕ Cin. Half-subtractor Borrow = A'B.
  • Decoder: n inputs → 2ⁿ outputs (converts binary to a specific output line). 1-of-32 from 3-to-8 decoders → 4; 4-to-16 from 2-to-4 → 5.
  • Encoder = 2ⁿ → n; priority encoder takes the highest input. MUX: 2ⁿ inputs need n select lines (data selector); DEMUX = distributor.
  • Selecting 1 of 8 doors → log₂8 = 3 switches.
  • Parity generation/checking → XOR/XNOR.
  • 2-bit comparator: A > B in 6 of 16 cases (formula (4ⁿ − 2ⁿ)/2; 3-bit → 28). Only one of A>B, A=B, A<B is 1 (1011 vs 1010 → A>B = 1, others 0).

Sequential circuits (flip-flops, counters)

  • SR latch: S=1 set, R=1 reset, 00 hold, 11 invalid (active-LOW NAND latch: 00 invalid). S=0,R=1 then R→0 → stays RESET.
  • JK: 00 hold, 10 set, 01 reset, 11 toggle. Toggle halves the frequency: 20 kHz → 10 kHz. Tie J=K → T flip-flop; D from JK: J = D, K = D'.
  • Gated D: Q follows D while enable is HIGH (SET or RESET as soon as D changes).
  • Master–slave: master enabled when clock HIGH, slave when LOW; cures race-around. Glitch caught while CLK is HIGH = ones catching.
  • Flip-flops needed = ⌈log₂N⌉: MOD-32 → 5, divide-by-128 → 7, MOD-10 → 4. Max count = 2ⁿ − 1.
  • Synchronous counter beats ripple delay because the clock is applied to every stage simultaneously.

Data representation

  • 2's complement = invert + 1: −5 → FB; −1 → FF; −12 → F4. 8-bit ranges: 1's complement / sign-magnitude −127 to 127 (two zeros); 2's complement −128 to 127.
  • Gray code = reflected code; one bit changes per step. Binary 101011 → Gray 111110 (copy MSB, XOR neighbours).
  • BCD 0001 0010 0110 = 126 = 1111110. BCD digits only 0000–1001. Excess-3 = BCD + 3.
  • IEEE 754 single = 1 + 8 (bias 127) + 23; double = 1 + 11 (bias 1023) + 52.
  • Booth's algorithm multiplies signed 2's-complement numbers (10 → subtract, 01 → add).
  • Overflow: two same-sign operands give an opposite-sign result.

CPU, memory transfer and control unit

  • MAR = address, MDR/DR = data, PC = next instruction, IR = current instruction.
  • Memory transfer operations = read and write. Read puts the address in MAR. Write loads the address into AR and the data into DR.
  • The location address is supplied by the CPU onto the address bus (bank key: CPU, not MAR). Memory bus = data bus (bank key).
  • Instruction cycle = fetch, decode, execute; the fetch starts with MAR ← PC.
  • Control memory is a ROM; microprograms are stored in ROM. Hardwired = fast, rigid; microprogrammed = flexible.
  • Control-memory addresses have 2 modes: executive and task; interrupts run in executive mode.
  • SDRAM = Synchronous DRAM; DDR2 = Double Data Rate 2; IRET = Interrupt return. DRAM needs refresh (capacitors); SRAM doesn't.

Instructions and addressing modes

  • An instruction code specifies the opcode and the address of the operand. Opcode of n bits → 2ⁿ operations.
  • 0-address = stack; 1-address = accumulator; 3-address = ADD R1,R2,R3. RISC = simple fixed-length load/store.
  • Immediate: operand inside the instruction (fastest). Direct: simplest mode that fetches from memory. Register: "a way of direct addressing". Indirect: memory holds the effective address (2 accesses). Register indirect: @R0. Implied: CMA.
  • Displacement EA = A + (R) is the "extremely influential" mode: relative (PC), base, indexed.

Pipelining

  • Improves throughput, not single-instruction latency. Time = (k + n − 1) cycles; speed-up = nk/(k + n − 1) → k. 5 stages, 100 instructions → 104 cycles.
  • Cycle time = slowest stage + latch delay. Hazards: structural (resource), data (RAW is the true dependency → forwarding), control (branches → prediction).

Memory hierarchy, cache, virtual memory

  • Registers > cache > RAM > disk: going down = bigger, slower, cheaper. Temporal locality = same item again; spatial = neighbours.
  • Cache search method = cache mapping. Direct: line = block mod lines (200 mod 64 = 8), no replacement policy needed. Fully associative: anywhere. Sets = lines / ways.
  • Hierarchical Tavg = hTc + (1 − h)(Tc + Tm): 0.9, 10, 100 → 20 ns. Simultaneous: hTc + (1 − h)Tm.
  • Write-through updates memory every time; write-back updates on eviction (dirty bit). Misses: compulsory, capacity, conflict.
  • Virtual memory: MMU translates; TLB caches translations; page fault = page not in RAM. EMAT = h(t + m) + (1 − h)(t + 2m).

I/O, DMA, interrupts, RAID

  • Programmed I/O = CPU polls (busy-wait); interrupt-driven; DMA = controller moves blocks, CPU only sets up (address, count) and gets an interrupt at the end. Cycle stealing vs burst.
  • Priority interrupt decides which request is served first; implemented by polling (software) or daisy chaining (hardware: nearest device = highest priority). NMI can't be masked; vectored = device supplies the ISR address.
  • RAID 0 striping (no redundancy); 1 mirroring; 2 Hamming; 3 byte + parity disk; 4 block + dedicated parity (bottleneck); 5 distributed parity (n − 1 usable); 6 double parity (n − 2, survives 2 failures); 10 = mirror + stripe.

Programming, Data Structures & Algorithms

C: pointers, arrays, strings, storage • Algorithm analysis and recursion • Stack • Queue, circular queue, deque • Arrays and linked lists • Sorting and searching • Trees, BST, AVL • Graphs and Dijkstra

C: pointers, arrays, strings, storage

  • Array name is a constant pointer: s++, ++x, x = y, x*2 → compile error; x + 1 is legal. Bank: illegal = I, III, IV.
  • int s[5] at 1000, 4-byte int: s + 1 = 1004, &s + 1 = 1020. *((int*)(&arr + 1) - 1) = last element (19).
  • p + p[1] - p[3] on "VITEEE2022": 'I' − 'E' = 4 → EE2022.
  • int s[5] = {1} → 1 0 0 0 0. int a[2][] = {...} is invalid (only the first dimension may be blank). int num[6] = {...} is the right syntax.
  • int (*p)[5] = pointer to an array of 5 ints; int *p[5] = array of 5 pointers.
  • const int *p / int const *p: *p = 100 or ++(*p) → compile error. static int x = num; (non-constant) → compile error.
  • Storage: global i → static area, local j → stack, malloc → heap. Passing a pointer by value to a function that mallocs → "May not work".
  • Static local keeps its value: test(1) with static number → 7. part1(5)/part2 → 53423122233445. fun(5) with x = 1 + Σfun(k)fun(n−k) → 51 (1, 2, 5, 15, 51).
  • Strings: strlen("function\0") = 8; "VIT\0Chennai" prints VIT; str2 = str1 → compile error; strcat into str1 then puts both → VIT Chennai / Chennai; strcpy(str2, strcat(str1, str2)) → VIT Chennai; {'V','I','T'} printed → VIT (bank).
  • arr[-2], arr[11] → garbage, garbage. arr[i] = ++i loop → Garbage, 1, 2, 3, 4. structure hotel → compiler error (keyword is struct). Proper struct: struct a_struct {int a;};. Structure = all the options; strncat appends ≤ n, strncmp compares ≤ n.

Algorithm analysis and recursion

  • Order: 1 < log n < n < n log n < n² < 2ⁿ < n!. 3n + 1 is linear. f = O(F) and g = O(F) ⇒ f + g = O(F). n² + 3n + 4 = O(n³).
  • Decreasing order with f4 = 2n (linear): f3, f1, f4, f2.
  • Master theorem: T = aT(n/b) + f(n); compare f with n^(log_b a). 7T(n/3) + n² log n → Θ(n² log n). Can't apply when f(n) is negative: 64T(n/8) − n² log n.
  • 2T(n/2) + n → n log n; T(n/2) + 1 → log n; T(n−1) + n → n²; 2T(n−1) + 1 → 2ⁿ.
  • Recursion advantage: less code, easy to implement (costs more memory). Pending work after the call = non-tail recursion. Backtracking: a node that can still lead to a solution is promising.

Stack

  • LIFO. Push 4, 8, 12, 16; pop 2 → push sum 28; pop 2 → push 36 → top 36. Push/pop sequence ending in an extra pop → underflow.
  • Impossible output check: after popping k, earlier items still inside must come out in reverse. Input 7,5,2,1,3,6 → impossible 2 1 3 6 7 5; pushes 0–9 → impossible 4 6 8 7 5 3 2 9 0 1.
  • Two-stack puzzle (Pop(A) moves to B) → prints 8 4 5 3 7 9.
  • Infix → postfix uses a stack. Postfix x 12 + z 17 y + 42 * / + = x + 12 + z / ((17 + y) * 42). Prefix + − * A B C D with 2,3,4,5 = 7.
  • Not stack uses: sorting and printing in original order (iii and iv). Stack from queues: minimum 1, efficiently 2. Queue from stacks: 2.

Queue, circular queue, deque

  • FIFO; used directly for scheduling and resource allocation. Multiplayer games → circular queue.
  • Insert: rear = (rear + 1) mod SIZE. Size 5, front 3, rear 4 → next index 0. Full when front = 0 and rear = MAX − 1 (or front = rear + 1); empty when front = rear.
  • front = 0, rear = maxsize − 1 with a count → count = maxsize (bank: 4).
  • Code that reads q[front], front++ → dequeue and return front. Recursive delete/recurse/insert → queue reversed.
  • Input-restricted deque = insert at one end, delete at both. Deque on singly linked list: delete rear = O(n).

Arrays and linked lists

  • Count = U − L + 1: AAA(5:50) and BBB(−5:10) → 46, 16.
  • Column-major A[1..5][1..10], base 50 → i + 5j + 44. Row-major: base + (i−L1)·cols + (j−L2).
  • Sparse {1, null×4, 10} → sizes 6 and 2. Arrays → spatial locality. Polynomial → linked list (coefficient, exponent).
  • Last node points to first, next pointers only → singly circular. No NULL next → circular. Next + prev → doubly.
  • 2-node circular doubly list: NOT true → Head->prev->next = tail. Cursor code that links p to CURSOR_SPACE[0] → releases space.

Sorting and searching

  • Bubble swaps = inversions: 5 1 4 3 2 → 7. {1, 2, 4, 3} needs 2 passes (second pass confirms).
  • Partition result 10 8 6 9 11 14 16 15 → either 11 or 14 could be the pivot.
  • Insertion sort condition: (j > 0) && (arr[j−1] > value); steps on 9 7 4 2 1: 79421 → 47921 → 24791 → 12479. With binary search still O(n²).
  • Quick sort worst n²; merge sort always n log n and stable; heap sort n log n in place.
  • Binary search on {45,77,89,90,94,99,100} for 99 → mids 90 then 99. Hashing O(1) average; linear probing → primary clustering.

Trees, BST, AVL

  • Height h (edges): max nodes 2^(h+1) − 1; max internal nodes 2^h − 1 (h = 7 → 127). Leaves = (2-child nodes) + 1.
  • A binary tree may be empty → "should have at least one node" is not valid.
  • Full tree from 8/15/13/14 nodes → 15 (bank uses "completely filled"). Trees with 10 nodes → 1014 (bank formula 2ⁿ − n).
  • BST insert 7,4,6,1,2,3,8,5 → height 4. Check BST = O(n). Inorder of a BST = sorted. Delete with 2 children → inorder successor.
  • AVL: balance factor ∈ {−1, 0, 1}, operations O(log n). LL → right rotation, RR → left, LR/RL → double. Minimum nodes N(h) = N(h−1) + N(h−2) + 1 → 1, 2, 4, 7, 12.

Graphs and Dijkstra

  • Complete graph: n(n−1)/2 edges; spanning trees of Kₙ = n^(n−2) → K₄ = 16. Spanning tree is never cyclic (false: "can be cyclic or acyclic").
  • Connected simple graph: incorrect inequality = v ≥ e/2. Planar: v − e + r = 2 → 6 vertices, 7 edges → 3 regions.
  • Adjacency matrix memory = O(n²). DAG: min in-degree + max out-degree → depends on the graph.
  • Graph vs tree traversal: loops (cycles); all three reasons (cycles, no root, multiple paths) → all of the above.
  • Visit all neighbours first → BFS. DFS applications: topological sort, SCCs, cycle detection; not P2P networks (BFS).
  • Dijkstra fails with negative weights → Bellman–Ford. Greedy, O((V+E) log V) with a heap. Prim/Kruskal = MST, not shortest paths.

Operating Systems

Basics • Processes and schedulers • Threads and IPC • CPU scheduling • Synchronisation • Deadlocks • Memory, virtual memory, files

Basics

  • OS = interface + resource manager + service provider → all. Services via system calls. Command interpreter = gets and executes the next user command.
  • Power-on program = bootstrap (initialises everything, starts the OS); choosing among several OSs = boot loader.
  • Not real-time: Palm OS. RTOS: Windows CE, RTLinux, VxWorks (all). RTOS: task must meet its deadline; hard RTOS has less jitter; interrupt latency minimal.
  • OS X = hybrid kernel. False statement: kernel modules can not be loaded while running (they can).
  • Trap/exception = software-generated interrupt caused by an error. OS sits in low or high memory, depending on the interrupt vector.
  • Transient code comes and goes and changes the OS size. Main memory accommodates the operating system (bank). OS handles all errors (paper, network, power); writes failures to a log file; responsible for bad-block recovery, booting, disk init → all.
  • Multiprogramming: more than one process in memory; goal = increase CPU utilisation; uses time productively. One process at a time = uniprocessing (bank); "uniprogramming vs multiprocessing" pair. Network OS runs on the server; distributed OS type = network OS.

Processes and schedulers

  • States: new, ready, running, waiting, terminated (no "old"). State = current activity. Quantum expires → ready; I/O done → ready; only self-initiated transition = block.
  • Stack holds parameters, locals, return addresses (not child PIDs). PCB = data structure; all PCBs in the process table; PCB lacks the bootstrap program and context-switch time. PC = next instruction.
  • Each process has its own address space, files, signals → all. Queues: job, ready, device (no "PCB queue"). I/O request → I/O queue. Terminated → removed from all queues.
  • Long-term → brings into the ready queue; short-term → picks the next and allocates CPU; medium-term → swaps out. Key difference = frequency. Degree of multiprogramming = processes in memory. All I/O-bound → ready queue empty, little work.
  • Dispatcher gives the CPU to the chosen process (assigns ready processes to CPU); dispatch latency = time to stop one and start another. CPU switch = process/task/context switch (all). TLB need not be saved. Scheduler process does not interrupt.
  • fork returns 0 to child, nonzero PID to parent; n forks → 2ⁿ processes. wait() suspends the parent. Child finished, parent running → zombie. Cascading termination: parent ends normally or abnormally / any one. Child can be a duplicate of the parent. Restricting child resources prevents creating too many sub-processes.

Threads and IPC

  • Thread has its own PC, registers, stack; shares code, data, files. One thread → one task at a time. Kernel can't schedule user-level threads. Multithreaded programs are more prone to deadlocks.
  • IPC = communication between processes; lets them communicate and synchronise. Cooperating process = can be affected by others.
  • Message passing works without a shared address space; operations send & receive; messages fixed or variable; link = communication link. Direct: link joins exactly two processes. Indirect: mailbox.
  • Non-blocking send: sends and resumes. Zero capacity: sender blocks until received = no buffering. Bounded/unbounded = automatic buffering. Remote IPC = RPC.

CPU scheduling

  • Basis of multiprogramming. Execution = CPU and I/O bursts; I/O-bound = many short CPU bursts. Selected from the ready queue by the short-term scheduler.
  • Non-preemptive scheduling when running → waiting (or terminating). Temporarily suspending runnable processes = preemptive. RR is preemptive; time quantum → RR; very large quantum → FCFS; short runtimes → quantum 15 ms.
  • Turnaround = submission → completion; waiting = time in ready queue; response = submission → first response; throughput = processes per unit time. Scheduling increases utilisation, decreases turnaround and waiting.
  • Multilevel queue = processes classified into groups; feedback = can move between queues. Priority: highest first; newcomer compared with the currently running process; static priority unchanged.
  • Starvation fix = aging. Perpetually denied = starvation. High priority indirectly preempted = priority inversion. SRTF and preemption may starve; RR beats FCFS on response → all three true.
  • SJF difficulty = knowing the next CPU burst; SJF priority = predicted next CPU burst (bank). FCFS troublesome for multiprogramming systems (bank; Galvin says time-sharing). Complex algorithms suit very large computers. Multiprogramming: short jobs shortened, long jobs lengthened.
  • Numericals: SJF P1=6, P2=8, P3=7, P4=3 → P1 waits 3 ms, average 7. FCFS 24,3,3 → average 17; RR q=4 → 5.66. SRTF classic (0/8, 1/4, 2/9, 3/5) → 6.5.

Synchronisation

  • Order-dependent outcome = race condition. One in the CS at a time = mutual exclusion. Bounded waiting = limit after a request and before it is granted. Minimum shared variables = 2 (Peterson: flag, turn).
  • Semaphore: integer accessed atomically; operations wait and signal; can't drop below zero. Mutual exclusion by mutex and binary semaphore. Sync at hardware and software level. Monitor encapsulates all three; waiting needs a condition variable.
  • signal → CS → wait: several processes in the CS. wait → CS → wait: deadlock.
  • Flags w1/w2 without turn → mutual exclusion but possible deadlock. S1==S2 / S1!=S2 strict alternation → bank key "both mutual exclusion and progress" (GATE official: ME but not progress).
  • S0=1 semaphore puzzle → P0 prints at least twice. 10 processes with P10 doing V → at most 3 in the CS. X = 5, A doubles, B adds 1 → 4 possible values; with a semaphore ordering them → 1.

Deadlocks

  • Deadlock = each process blocked forever. Conditions: mutual exclusion (a non-sharable resource), hold and wait (holding one, waiting for more), no preemption, circular wait.
  • Prevention = ensure at least one condition cannot hold. Circular wait → linear ordering of resource types. All resources up front → low resource utilisation. No-preemption fix → preempt all held resources. Sharable resources need no mutual exclusion.
  • Avoidance needs the maximum demand; examines the resource-allocation state; considers resources currently available (bank); requires a fixed number of resources. Safe state = can allocate in some order (bank option A) ⇔ a safe sequence.
  • 12 drives, max 10/4/9, allocated 5/2/2 → safe sequence P1, P0, P2. Galvin 5-process snapshot → safe (P1, P3, P4, P2, P0).
  • RAG not applicable with multiple instances; Banker's is less efficient than RAG. Wait-for graph: single instance; Pi → Pj = Pi waits for Pj; cycle ⇒ deadlock. Frequent deadlocks → detect frequently; check at requests at fixed intervals (bank).
  • Request/release = system calls; reusable resource = one process at a time, not depleted. Minimum units for n processes needing k: n(k − 1) + 1.

Memory, virtual memory, files

  • Protection: every CPU address checked against relocation and limit registers. OS keeps a frame table. Dynamic loading needs no special support. Never swap with pending I/O. Device drivers give a uniform interface. Memory-mapped I/O: write a data byte and set a control bit.
  • First/best/worst fit; external fragmentation → compaction/paging; paging has internal fragmentation only. 32-bit address, 4 KB pages, 4-byte entries → 4 MB page table.
  • Working sets exceed frames → suspend a process. Thrashing = more paging than executing. Belady's anomaly = FIFO with more frames → more faults. Classic string, 3 frames: FIFO 15, LRU 12, OPT 9.
  • File info in a directory structure; open files in the open-file table; single-level = all files in one directory; OS ignores links when traversing to stay acyclic.
  • Allocation: contiguous (external fragmentation), linked (no random access), indexed (inodes). Disk: FCFS 640, SSTF 236 on the classic queue; SSTF can starve; SCAN = elevator.

Database Management Systems

Concepts, users, architecture • ER model • Relational model and relational algebra • SQL • Functional dependencies and normalisation • Indexing and B/B+ trees • Transactions, concurrency, recovery • NoSQL

Concepts, users, architecture

  • Schema = structure (rarely changes); database state = data at a moment (4 pm snapshot); catalog/data dictionary = metadata (data about data). The net-banking screen = a view.
  • Three levels: internal, conceptual, external. Physical data independence = change storage without changing the conceptual schema; logical = change the conceptual schema without changing apps (harder).
  • Pre-compiler extracts embedded SQL (DML) from host-language programs.
  • Users: naive/parametric (canned transactions, bank tellers), casual (occasional ad-hoc queries), sophisticated (engineers, analysts), standalone; plus DBA, designers, programmers.
  • Standalone app → single-tier; web app → three-tier. Research documents → textual database. Supermarket schema constructs → all.

ER model

  • Entity = rectangle, attribute = oval, relationship = diamond ("registers" goes inside a diamond between 2 rectangles). Weak entity = double rectangle; multivalued = double oval; derived = dashed oval.
  • Contact number split into country code + number, address into door/street/city/zip → composite. Phone numbers → multivalued. Experience from date of joining → derived. Simple attribute (bank) → name. Key of PROJECT → ProjectId. SHIPPING(shippingId, ShipLocations) → composite key.
  • Student registers many courses → M:N. Athlete max 3 activities → 1:3. Doctor–patient diagnoses → M:N. Instructor's function in "teaches" → role. "Customer buys Products" → relationship set Buys. ProductName is not an entity set.
  • Weak entity SLOT: false statement = no existence dependency on TIMETABLE. Investor buys/sells shares → recursive relationship (bank).
  • MovieZone → Hollywood/Bollywood = specialization; SENSE, SELECT, SCOPE → DEPARTMENTS = generalization. Subclass SHIPPING inherits all ORDERS attributes + its own. Adding a superclass attribute propagates under both attribute- and predicate-defined membership.

Relational model and relational algebra

  • Super key ⊃ candidate key (minimal) ⊃ primary key; foreign key → referential integrity; PK not NULL → entity integrity. Degree = columns, cardinality = rows.
  • Super keys of R(A..H) with key H = 2⁷ = 128. Candidate keys AB, AC, DE: "not a proper subset" → DE (bank).
  • π picks columns: SELECT city FROM store = πcity(store). σ picks rows: stores in India = σcountry='India'(store). × multiplies rows, adds columns; ∪/−/∩ need union compatibility; ÷ answers "for all".

SQL

  • DDL: CREATE, ALTER, DROP, TRUNCATE. DML: SELECT, INSERT, UPDATE, DELETE. DCL: GRANT, REVOKE. TCL: COMMIT, ROLLBACK, SAVEPOINT.
  • Unique values → DISTINCT. SELECT * → all fields. Change Mishra → Singh: UPDATE People SET LastName='Singh' WHERE LastName='Mishra'.
  • WHERE filters rows, HAVING filters groups. Male-employee GROUP BY with HAVING avg > company avg → departments where male average salary is more than the organisation average. NULL check: IS NULL.

Functional dependencies and normalisation

  • Closure: AB→C, C→DE, E→F, D→A, C→B gives AB⁺ = ABCDEF. Attributes never on a right side are in every key.
  • R(A,B,C,D), AB→CD, D→B, C→A → 4 candidate keys (AB, AD, BC, CD). AB→CD, D→B: extraneous attribute = none.
  • R(ABCDE) with AE→BC, AC→D, CD→BE, D→E: non-prime = B. AB→C, B→EF, AD→G → key {A, B, D}.
  • A→BC, B→CF, E→A, F→E on ABCDEF → 4 keys (AD, BD, ED, FD); C depends on part of a key → 1NF, not 2NF.
  • A→BCD, BC→AD, D→B → all attributes prime, D→B violates BCNF → 3NF.
  • Lossless if the common attributes are a key of one side: A→B, C→AB, R1(C,A)/R2(A,B) lossless and R1(A,B)/R2(B,C) lossy → both I and II.
  • 2NF removes partial dependency; 3NF removes transitive (X super key or A prime); BCNF: every determinant is a super key. BCNF ⇒ 2NF and 3NF. False statement: lossless (dependency-preserving) BCNF decomposition is always possible. Any 2-attribute relation is in BCNF.

Indexing and B/B+ trees

  • Indexes slow updates; large keys make the engine's task tougher. Data ordered like the index → clustered. Index built on the first level = second level of a multilevel index. Key-to-position formula → hashed file.
  • B-tree order 4: max 3, min 1 keys. B+ tree with max 7 keys → min 3 in non-root nodes. Order-4 B-tree, 8 insertions → at most 3 splits.
  • B+ tree: data pointers only in leaves (false: non-leaf nodes point to records), leaves linked, balanced because all root-to-leaf paths are equal; range queries are faster on B+ trees.
  • 4 KB node, 40-byte entry, 1 million keys → height 4 (⌈log₅₀ 10⁶⌉). Hash index = equality only; B+ tree = equality + range. Index-only GROUP BY eno → any index type, clustered or not.

Transactions, concurrency, recovery

  • ACID: atomicity (all or nothing), consistency, isolation, durability (survives any failure). Concurrency does not reduce deadlock probability; it ensures no interference. Bank: "which is false" about recovery/concurrency responsibilities → none.
  • Invalid schedule: W(X), W(Y), R(X), R(Y) (breaks transaction order). Conflict = same item, different transactions, ≥ 1 write: W1(X), R2(X).
  • Conflict serializable: R1(X), W1(X), R2(Y), R2(X), W2(X), R1(Y). r1(X) w3(X) w3(Y) w2(Y) r1(Z) w3(Z) w2(Z) → both view and conflict serializable; r1(y) r2(x) … r1(x) → both. Not every schedule is serializable.
  • Recoverable schedule S → only I. Reading data written by an uncommitted transaction → irrecoverable mistake.
  • Isolation: no dirty or non-repeatable reads but phantoms allowed → repeatable read. Highest concurrency → row-level locking.
  • Strict 2PL schedules are recoverable; Thomas' write rule gives view- but not conflict-serializable schedules → II only. Basic TO ⊆ multiversion TO. Two-phase commit (bank) → ensures serializability.
  • Not a recovery technique: two-phase commit. Rollback → recover from transaction failure. Deferred update = redo only; immediate = undo + redo; WAL; checkpoints; shadow paging.

NoSQL

  • NoSQL is schema-less; incorrect statement: schemas must be defined before adding data. Handles mainly unstructured data.
  • Types: key-value (Redis), document (MongoDB), wide-column (Cassandra, HBase), graph (Neo4j). "Which are NoSQL databases": bank key Key-value, truth all. CAP: pick two of consistency, availability, partition tolerance.

Computer Networks & Cryptography

Switching, Frame Relay, ATM • Models, topologies, devices, signals • Error detection and correction • IP addressing and routing • Transport, sockets, congestion, applications • Cryptography • Signatures, keys, authentication, security protocols

Switching, Frame Relay, ATM

  • Circuit switching: dedicated path, connection-oriented, works at the physical layer; best for constant-rate, long-duration traffic.
  • Packet switching: store and forward, at the network layer; datagram = connectionless. Virtual circuit: all packets follow the same route, uses global and local addressing; router failure → all VCs through it terminate.
  • Switched network nodes = switches. Crossbar 30 × 30 → 900 crosspoints. Bursty data = rate changes suddenly in a short time.
  • Frame Relay: virtual circuits, no error/flow control. ATM: 53-byte cells (5 header + 48 payload), VPI/VCI. AAL1 constant bit rate; AAL3 connection-oriented data; AAL4 connectionless; AAL5 simple data.

Models, topologies, devices, signals

  • OSI: physical, data link, network, transport, session, presentation, application. TCP/IP has no session layer (or presentation).
  • Physical = transmission speed; data link = flow control (and framing, MAC); network = routing, internetworking (odd one out: error control); transport aggregates process data and passes it to the network layer; presentation = encryption/decryption.
  • IPv4 header 20 bytes + 20 options = 40; maximum 60.
  • Mesh: n(n−1)/2 cables, n−1 ports → 10 devices 45, 9; highest reliability; leads to redundant connections. Star = each device to a central node. Classic Ethernet = bus.
  • Hub = layer 1, switch = layer 2 (bank key; also forwards only to the destination). Router connects different networks; gateway connects different protocols. Router non-functions (bank): i, iv, vi.
  • LAN: a few km, up to 1000 Mbps. Internet = WAN. Half duplex = walkie-talkie. MAC = 48 bits (07:01:02:01:2C:4B); IPv4 = 32 bits.
  • Analog = infinite values in a range; analog and digital can be periodic or non-periodic; one full pattern = cycle. Bandwidth = high − low: 1 kHz to 40 MHz → 39.999 MHz. Nyquist 2B log₂L; Shannon B log₂(1 + SNR). Broadcast = one-to-all.
  • Configuration management = documenting hardware and software changes.

Error detection and correction

  • Two or more bits changed = burst error; 10100101 → 10100100 = single-bit error.
  • Hamming distance: 10101010 vs 01010101 = 8; 10101 vs 11110 = 3. Detect s errors: d = s + 1; correct t: d = 2t + 1.
  • Simple parity detects an odd number of errors. Checksum = 1's complement. Modulo-2: 1 + 1 = 0. CRC = XOR division (1001 / 1011 → 110).
  • Hamming: 2^r ≥ m + r + 1. Syndrome 0101 → bit 5 in error.

IP addressing and routing

  • Classes: A 1–126, B 128–191, C 192–223 (11011110 = 222 → C), D 224–239 multicast. Internet-facing host → public address.
  • 12.12.12.12/20 → network 12.12.0.0 (/20 mask 255.255.240.0). Hosts = 2^h − 2 (/26 → 62).
  • ARP maps logical → physical address. IPv6 = 128 bits; traffic class ≈ ToS; hop limit ≈ TTL.
  • Static routing table = manually configured. Intra-domain: distance vector (RIP = intra-domain distance vector), link state (OSPF — can use throughput as cost). Inter-domain: path vector (BGP), used between autonomous systems.

Transport, sockets, congestion, applications

  • TCP = connection-oriented, reliable, supports error and flow control; UDP doesn't. Socket address = IP + port. TCP server doesn't call connect().
  • Sending window = min(rwnd, cwnd) = min(5 KB, 2 KB) = 2 KB. 100 frames in a sliding window → ACKs ≤ 100 (cumulative).
  • Node-to-node congestion control = back pressure (choke packet goes to the source). Discarding policy prevents congestion without harming integrity. TCP: slow start doubles cwnd, then +1; timeout → ssthresh = cwnd/2, cwnd = 1.
  • Application protocols: HTTP, SMTP, SNMP (not ICMP, IGMP, ARP). FTP is client–server; 10 files → 11 connections (1 control + 10 data). Receiver fetches mail with IMAP (or POP3); SMTP sends.

Cryptography

  • Public-key purpose: encryption, authentication, key exchange → all. Encrypt with the public key; keep the private key secret. Key-pair generation → RSA.
  • Same key → symmetric (faster); different keys → asymmetric ("more secure" per bank). PKC advantage = simpler key management.
  • AES: 128-bit block; 128, 192 or 256-bit keys; AES-256 = 14 rounds (128 → 10, 192 → 12). S-AES key = 16 bits. DES: 64-bit block, 56-bit key, 16 rounds.
  • RSA: n = pq, φ = (p−1)(q−1), ed ≡ 1 mod φ (p = 3, q = 11, e = 7 → d = 3). Diffie–Hellman (q = 23, α = 5, a = 6, b = 15 → key 2) is open to man-in-the-middle.
  • Caesar HQFUBSWHG WHAW → ENCRYPTED TEXT (shift back 3). Encryption gives confidentiality but not integrity.
  • Attacks: guessing until right = brute force; pre-computed hashes = rainbow table; tricking people = social engineering; intercept and modify = man-in-the-middle.

Signatures, keys, authentication, security protocols

  • Digital signature = message encrypted with the private key; created with the private key, verified with the public key; Anarkali → Salim needs Anarkali's public key. Algorithm → RSA; needs a public-key system.
  • Provides authentication and non-repudiation (and integrity), not confidentiality; for confidentiality add a cryptosystem. Main purpose = authentication; required for non-repudiation. Conventional signature is included in the document, digital is separate; relation = one-to-one. Birthday attack possible by S only.
  • Data origin authentication → MAC (MDC = integrity only). Exactly as sent = integrity.
  • Key distribution: not a means = hashing certificates; most secure = public-key certificates; trusted third party distributing keys = public-key authority; saving keys = caching. X.509 subject unique identifier added in v2. KDC creates a session key, used only once.
  • Authentication = verifying identity. Password = something you know. Password + token, smart card + PIN → two-factor; biometric alone → single-factor; multiple factors → multi-factor. CHAP = Challenge Handshake Authentication Protocol. Kerberos = authentication server + ticket-granting server.
  • Firewall = rule-based traffic control. Layer-4 firewall can't block traffic from a specific user. Dynamic packet filters work on TCP, UDP. Secure web = HTTPS; secure remote login = SSH; SSL gives integrity and confidentiality; email = PGP; transport/tunnel modes = IPSec; IP-level authentication = AH (ESP encrypts).

Machine & Deep Learning

Linear and logistic regression • SVM and kernels • kNN • Clustering and SOM • Trees, ensembles, Naive Bayes • Semi-supervised and unsupervised learning • CNNs and detection • Reinforcement learning and DQN

The ML and Big Data banks have no official key; the answers below are worked out and verified.

Linear and logistic regression

  • Y rises as X rises → positive linear. Best-fit line = minimum sum of squared residuals. Regression metric = R² (recall/precision/F are classification).
  • Y = 55.1 + 0.28X → Y changes by the slope per unit X. R² = 1 − SSE/SST = 1 − 75/400 = 0.81.
  • Error assumptions: mean 0 (not one), equal variance, independent, normal. Age vs date of birth → strong negative correlation (r ≈ −1).
  • Swap X and Y → SSE changes (r, R², slope sign don't). Normalising the target changes SSR because the outcome scale differs. Multicollinearity = correlated predictors.
  • Pass/fail → logistic regression. Sigmoid σ(0) = 0.5, range (0, 1). Odds = P(for)/P(against); P = 0.75 → odds 3. Trained with log loss; e^b = odds ratio; multi-class → softmax.

SVM and kernels

  • Maximum-margin hyperplane; margin = 2/‖w‖; closest points = support vectors. Points (3,+1), (1,+1), (−1,−1) → w = 1, b = 0.
  • Kernel trick = inner products in a higher-dimensional space. Linear x·y; polynomial (x·y + c)^d; RBF exp(−γ‖x−y‖²) (large γ overfits). Valid kernel ⇔ Mercer (PSD). Large C = narrow margin. XOR is not linearly separable.

kNN

  • Lazy, non-parametric: makes no assumption on the data; classification and regression; used for imputing missing values.
  • Predicts the most frequent class among the k nearest. Noisy data → increase k. As k increases, bias increases (variance falls, boundary smoother). 2-NN vs 4-NN → higher variance, lower bias.
  • Categorical attributes → Hamming distance. Manhattan (1,1)–(5,4) = 7 (Euclidean 5). Scale features first.

Clustering and SOM

  • k-means assigns to the nearest centroid, suits high-dimensional data; choose k with the elbow method; sensitive to outliers; not deterministic across initialisations; can't find non-convex clusters. Categorical alternative → k-modes.
  • {2, 6, 10, 14, 18, 7}, centres 4 and 12 → 5 and 14. Correlation 1 between x1, x2 → centroids on a straight line.
  • A = {0,2,5}, B = {3,10}, C = {12}: single linkage merges AB (distance 1), complete linkage merges BC (max 9).
  • SOM (Kohonen): unsupervised competitive neural network, topology-preserving 2-D map. Incorrect statement: "it doesn't involve neural networks". Updates the winning neuron and its neighbours.

Trees, ensembles, Naive Bayes

  • Entropy (50/50) = 1; Gini (50/50) = 0.5; ID3 uses information gain.
  • Bagging = random subsamples with replacement; reduces variance. Random forest = bagging + random feature subsets.
  • AdaBoost: weight increases if misclassified by the round-t weak learner; learners below 0.5 accuracy are dropped because they'd get negative weights. α = ½ ln((1−ε)/ε).
  • Naive Bayes: conditional independence. n Boolean features + Boolean label → 2n + 1 parameters; 4 inputs → 9. Infinite perfect data → may not achieve either zero training or zero test error.

Semi-supervised and unsupervised learning

  • Semi-supervised = few labels + many unlabelled points (self-training, co-training, label propagation).
  • EM for MAP instead of ML → modify the Maximization step.
  • Autoencoder reconstructs its input through a bottleneck; RBM → contrastive divergence; stacked RBMs = DBN; Hebbian = fire together, wire together.
  • Gradients through sigmoid/tanh cannot change sign (only shrink; sigmoid' ≤ 0.25).

CNNs and detection

  • Conv output = (W − F + 2P)/S + 1 (32, 5×5 → 28; AlexNet 227, 11, stride 4 → 55). Params = (F·F·C_in + 1) × K. 2×2 pool halves W and H.
  • LeNet-5 (1998, digits); AlexNet (2012, ReLU, dropout, GPUs); VGG (3×3 only); GoogLeNet (Inception, 1×1 bottleneck); ResNet (adds skip connections, y = F(x) + x).
  • R-CNN: selective search ~2000 regions → CNN per region → SVMs (slow). Fast R-CNN: one CNN pass + RoI pooling. Faster R-CNN: Region Proposal Network with anchors. Mask R-CNN: masks + RoIAlign. IoU = overlap/union.
  • YOLO: one-stage, real-time; 7 × 7 grid, 2 boxes, 20 classes → 7 × 7 × 30; cell containing the centre is responsible; weak on small grouped objects.
  • DenseNet: each layer gets all earlier feature maps, concatenated; L(L+1)/2 connections; growth rate k; output channels k₀ + Lk; transition = 1×1 conv + 2×2 avg pool; fewer parameters.

Reinforcement learning and DQN

  • Optimal policy → Q-learning (direct evaluation and TD only estimate V for a fixed policy). Q ← Q + α[r + γ max Q' − Q].
  • DQN: CNN approximates Q from pixels (Atari); experience replay + target network; ε-greedy exploration. Double DQN fixes overestimation; Dueling DQN splits V and A.

Methodology and competing on analytics

  • IBM methodology (10 stages, iterative): business understanding → analytic approach → data requirements → data collection → data understanding → data preparation (longest) → modeling → evaluation → deployment → feedback.
  • Guiding questions: problem? (business understanding); how can data answer it? (analytic approach); is the data representative? (data understanding); does the model answer the question? (evaluation).
  • Analytics types: descriptive (what happened), diagnostic (why), predictive (what will happen), prescriptive (what to do). CRISP-DM = 6 phases.
  • Davenport & Harris: analytical competitors use analytics as the main competitive advantage, enterprise-wide, with senior-management commitment.
  • Internal processes: finance, M&A, operations, R&D, HR (Moneyball). External: customer (Harrah's loyalty, Capital One test-and-learn, Netflix) and supplier (Walmart Retail Link, UPS routing).
  • Five stages: analytically impaired → localised analytics → analytical aspirations → analytical companies → analytical competitors. DELTA = Data, Enterprise, Leadership, Targets, Analysts.

Visualisation

  • Trend → line; compare categories → bar; one variable's distribution → histogram; two numeric variables → scatter; median, quartiles, outliers → box plot; parts of a whole → pie; correlation matrix → heatmap.
  • Truncated axes mislead; maximise the data-ink ratio. Matplotlib plt.hist / plt.scatter; Seaborn pairplot, heatmap.

Regression and linear optimisation

  • Coefficient = change in Y per unit X holding others constant. np.polyfit(x, y, 1) → [slope, intercept]; sklearn .coef_, .intercept_, .score() = R². Normal equation b = (XᵀX)⁻¹Xᵀy. Categories → dummy variables.
  • LP = decision variables + objective + constraints; the optimum is at a corner point. Max 3x + 2y with x + y ≤ 4, x + 3y ≤ 6 → 12 at (4, 0). Max 5x + 4y with 6x + 4y ≤ 24, x + 2y ≤ 6 → 21 at (3, 1.5).
  • Infeasible = no feasible point; unbounded = improves forever; binding = zero slack; shadow price = objective change per extra unit of RHS. linprog minimises; simplex hops vertices.

NumPy

  • A = [[1,2],[3,4]]: A * A = [[1,4],[9,16]] (element-wise); A @ A = [[7,10],[15,22]]; det = −2; inv = [[−2, 1], [1.5, −0.5]].
  • np.linalg.solve([[2,1],[1,3]], [3,5]) → x = 0.8, y = 1.4. np.eye(3) identity; norm([3,4]) = 5; rank [[1,2],[2,4]] = 1; dot([1,2,3],[4,5,6]) = 32.
  • (2×3)@(3×4) → (2×4). Broadcasting (3,1)+(1,4) → (3,4). sum(axis=0) per column, axis=1 per row. arange(10)[2:8:2] = [2, 4, 6].

Pandas and JSON

  • Series = labelled 1-D array; dict keys become the index; s['b'] by label, s.iloc[0] by position; arithmetic aligns on index (unmatched → NaN); mean() skips NaN; value_counts() = frequencies.
  • DataFrame: shape = (rows, cols); describe() = count, mean, std, min, 25%, 50%, 75%, max; info() = dtypes, non-null counts.
  • loc = labels, end included (loc[0:2] → 3 rows); iloc = positions, end excluded (2 rows). Filter with & and parentheses.
  • groupby('dept')['s'].mean(); merge(..., how='left') keeps all left rows; concat stacks rows; dropna() drops rows; fillna(0); drop(columns=[...]); apply(axis=1) per row.
  • I/O: read_csv, read_json, read_sql, to_csv(index=False). json: load/dump = files, loads/dumps = strings. to_json(orient='records') → list of row dicts; DataFrame default orient = columns; lines=True for JSON Lines; json_normalize flattens nesting. JSON keys use double quotes; [ ] arrays, { } objects.

Probability and EDA

  • Binomial mean np, variance np(1−p) (n=10, p=0.5 → 5, 2.5); P(X=2 | n=4, p=0.5) = 0.375. Poisson mean = variance = λ; P(0) = e^−λ. Geometric = trials to first success.
  • Normal 68/95/99.7; z = (x − μ)/σ. Uniform mean (a+b)/2, variance (b−a)²/12. Exponential mean 1/λ, memoryless. Continuous P(X = x) = 0; PMF discrete, PDF continuous. CLT: sample means → normal.
  • EDA (Tukey): explore before modelling. Median is robust; mean > median → right skew. IQR = Q3 − Q1; outliers beyond Q1 − 1.5·IQR or Q3 + 1.5·IQR (Q1 20, Q3 40 → −10 and 70). isnull().sum() = missing per column; corr(); correlation ≠ causation.

Big Data Computing & Business Analytics

Architecture and Hadoop

  • 3 Vs: volume, velocity, variety. Pipeline: ingest (Kafka, Flume, Sqoop) → store (HDFS, data lake, warehouse) → process (Spark = processing and analytics) → serve → BI tools make dashboards.
  • Not a framework: Apache Picasso. Columnar DB benefit = faster query performance. OLAP = Online Analytical Processing (roll-up, drill-down, slice, dice). Open-source storage + processing = Hadoop.
  • Hadoop strengths: high fault tolerance and scalability (batch, not real-time). HDFS = Hadoop Distributed File System: 128 MB blocks, replication 3.
  • NameNode stores metadata (files, directories, block locations); DataNodes store blocks and send heartbeats; Secondary NameNode only checkpoints.
  • YARN manages and schedules resources (ResourceManager, NodeManager, ApplicationMaster). SQL on HDFS = Hive; Pig = scripts; HBase = NoSQL; Sqoop = RDBMS ↔ HDFS; Oozie = workflows.

MapReduce

  • Map = transform data into key-value pairs; shuffle and sort; Reduce aggregates. Jobs in Java and Python (Streaming).
  • Consolidates the Map outputs = Reduce. Processes chunks and produces output = Maptask. Maps input pairs to intermediate pairs = Mapper.
  • Word count "big data big" → map (big,1)(data,1)(big,1) → reduce (big,2)(data,1). Combiner = local reduce; partitioner picks the reducer; #maps = #input splits.

Spark, SparkContext, RDDs

  • SparkContext (in the driver) gets resources from the cluster manager at the executor level. Parallelism setting = spark.default.parallelism. setCheckpointDir = directory for checkpoint data. Spark 2+ wraps it in SparkSession.
  • Optimisation phase (pipelining narrow transformations, choosing the physical plan) = query optimization. Data locality = run tasks near data, less network overhead.
  • RDD immutability → fault tolerance and lineage; lineage matters during transformations (lost partitions recomputed). Advantage over HDFS = in-memory processing.
  • Create RDDs: sc.parallelize, sc.textFile, or transform another RDD.
  • Transformation (lazy) = reduceByKey, map, filter, flatMap, join. Actions = count, collect, take, saveAsTextFile. Lazy = computed only when an action is called.
  • Full shuffle = reduceByKey (wide); map and filter are narrow. Cache when an RDD is computed multiple times. reduceByKey beats groupByKey (combines locally).

Analytics lifecycle and KDD

  • Lifecycle: discovery (objectives, KPIs) → data preparation (longest) → model planning → model building → communicate results → operationalise.
  • Bank wording: objectives and KPIs → Data Exploration (earliest listed; truly Discovery). Validating on real-world data and adjusting → Data Deployment.
  • Unstructured data challenges = integration and quality → governance + ETL. KDD = Knowledge Discovery in Databases. Attribute varying over time = time series analysis.

Association and sequence rules

  • Frequency of an itemset = support count (support = count / N). Frequent itemset = support ≥ minimum support.
  • Confidence(A→B) = Support(A∩B) / Support(A). Lift = confidence / support(B); 1 = independent.
  • Basket example (5 transactions): sup{Milk, Diaper, Beer} = 0.4; conf({Milk, Diaper}→Beer) = 0.67; conf(Diaper→Beer) = 0.75; lift 1.25.
  • Apriori: every subset of a frequent itemset is frequent. Efficiency boosters: hash-based techniques, transaction reduction, partitioning, sampling. FP-Growth avoids candidate generation.
  • Sequence rules: order matters (laptop → bag → mouse); GSP (Apriori-style), SPADE, PrefixSpan; uses: clickstreams, purchase histories.

Graph analytics and social network metrics

  • Techniques: shortest paths, PageRank (damping 0.85), community detection, connected components, triangle counting. Tools: GraphX, Pregel (vertex-centric BSP), Neo4j (Cypher).
  • Degree centrality = direct ties (normalised degree/(n−1)); betweenness = on many shortest paths (broker; star centre is highest); closeness = shortest total distance; eigenvector = tied to important nodes.
  • Density = edges / [n(n−1)/2] (5 nodes, 4 edges → 0.4). Clustering coefficient = linked neighbour pairs / possible pairs. Diameter = longest shortest path. Homophily = similar people connect. In-degree = popularity.

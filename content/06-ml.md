# linreg | Linear & Multiple Linear Regression
N: **Simple linear regression**: Y = b₀ + b₁X + ε. **Slope b₁** = change in Y for a 1-unit change in X; **intercept b₀** = Y when X = 0. Y = 55.1 + 0.28X → Y changes by 0.28 (the slope) per unit of X.
N: **Least squares** picks the line that **minimises the sum of squared residuals (SSE)** — that is the best-fit line. b₁ = Σ(x−x̄)(y−ȳ) / Σ(x−x̄)², b₀ = ȳ − b₁x̄.
N: **R² (coefficient of determination)** = 1 − SSE/SST = SSR/SST (0 to 1). SST = 400, SSE = 75 → R² = 0.8125. **Adjusted R²** penalises extra predictors. R² is the key metric for regression models (recall, precision and F-score are classification metrics).
N: **Correlation r** ∈ [−1, 1]: strong positive → close to +1, strong negative → close to −1. r² = R² in simple regression. Swapping X and Y keeps r, R² and the slope's sign but changes SSE.
N: **Assumptions on the error ε (LINE)**: Linearity, Independence of errors, Normality, Equal variance (homoscedasticity), and **E(ε) = 0** (NOT 1).
N: **Multiple linear regression**: Y = b₀ + b₁X₁ + … + bₖXₖ. Problem: **multicollinearity** (check VIF). Each coefficient is the effect holding the other variables constant.
N: Error metrics: **MSE, RMSE, MAE**. Gradient descent can also fit the model iteratively. Scaling the target changes the size of the residuals (and SSE).
N: Positive linear relationship: Y increases as X increases (upward slope). Negative: Y decreases as X increases.

# logreg | Logistic Regression
N: **Logistic regression** = **classification** (binary: pass/fail, fire/no fire). Output P(Y=1) = **σ(z) = 1 / (1 + e^−z)**, z = b₀ + b₁x₁ + …. σ(0) = 0.5.
N: **Odds** = P / (1 − P) = probability the event happens ÷ probability it doesn't. P = 0.75 → odds = 0.75/0.25 = **3**. **Log-odds (logit)** = ln(P/(1−P)) is linear in the inputs.
N: The coefficient bᵢ changes the log-odds by bᵢ per unit of xᵢ; **e^bᵢ = odds ratio**.
N: Trained by **maximum likelihood**, i.e. minimising **log loss / binary cross-entropy** (not SSE). Decision threshold usually 0.5.
N: Multi-class → **softmax (multinomial) regression** or one-vs-rest.
N: Classification metrics: accuracy, **precision = TP/(TP+FP)**, **recall = TP/(TP+FN)**, F1 = 2PR/(P+R), confusion matrix, ROC-AUC.

# linnon | Linear vs Non-linear Models & Kernel Functions
N: **Linearly separable** data can be split by a straight line/hyperplane. **XOR** is the classic non-linearly-separable problem (a single perceptron can't learn it).
N: **SVM** finds the **maximum-margin hyperplane** w·x + b = 0; margin = 2/‖w‖. Points on the margin are **support vectors** (only they define the boundary).
N: **Hard margin**: no misclassification (separable data). **Soft margin**: slack variables; **C** large → narrow margin, low bias / high variance; C small → wide margin, more regularisation.
N: **Kernel trick**: compute inner products in a high-dimensional feature space without mapping explicitly: K(x, y) = φ(x)·φ(y). Kernels must be symmetric positive semi-definite (**Mercer's condition**).
N: Common kernels: **Linear** x·y; **Polynomial** (x·y + c)^d; **RBF/Gaussian** exp(−γ‖x − y‖²) (infinite-dimensional; large γ → wiggly boundary/overfit); **Sigmoid** tanh(αx·y + c).
N: Non-linear models: polynomial regression, kernel SVM, decision trees, kNN, neural networks.

Q: For a dataset of three points {(3, 1), (1, 1), (−1, −1)} written as (x, label), what are w and b given by a hard-margin SVM?
* w = 1, b = 0 ~~ The closest opposite points are x = 1 (+1) and x = −1 (−1): w·1 + b = 1 and −w + b = −1 → w = 1, b = 0. The boundary is x = 0.
- w = 1, b = 1 ~~ Boundary at x = −1 touches a point.
- w = 0, b = 1 ~~ w = 0 can't separate anything.
- w = 0, b = 0 ~~ No boundary.
H: Margin lines pass through the support vectors x = ±1.
P: PYQ (no key)

Q: In an SVM, the data points that lie closest to the decision boundary and define it are called:
- Centroids ~~ Clustering.
* Support vectors ~~ Removing other points doesn't change the boundary.
- Outliers ~~ Not necessarily.
- Kernels ~~ Functions, not points.
H: Support vectors support the margin.

Q: The margin of a linear SVM with weight vector w is:
- ‖w‖ ~~ Inverse relationship.
* 2 / ‖w‖ ~~ Maximising the margin = minimising ‖w‖.
- 1 / 2‖w‖ ~~ No.
- w·x ~~ That's the score.
H: Maximise 2/‖w‖ ⇔ minimise ½‖w‖².

Q: The kernel trick allows SVMs to:
* Learn non-linear boundaries by implicitly mapping data to a higher-dimensional space ~~ Only inner products K(x, y) are needed.
- Reduce the number of support vectors to one ~~ No.
- Avoid using any training data ~~ No.
- Turn regression into clustering ~~ No.
H: Kernel = dot product in a hidden feature space.

Q: The RBF (Gaussian) kernel is defined as:
- (x·y + c)^d ~~ Polynomial.
* exp(−γ‖x − y‖²) ~~ Similarity decays with squared distance.
- x·y ~~ Linear.
- tanh(αx·y + c) ~~ Sigmoid.
H: RBF = Gaussian bump around each point.

Q: The polynomial kernel of degree d is:
* K(x, y) = (x·y + c)^d ~~ Captures feature interactions up to degree d.
- K(x, y) = exp(−γ‖x−y‖²) ~~ RBF.
- K(x, y) = x·y ~~ Linear.
- K(x, y) = ‖x − y‖ ~~ A distance, not this kernel.
H: Polynomial = (dot + c)^d.

Q: Which condition must a function satisfy to be a valid kernel?
- It must be linear ~~ Many valid kernels are non-linear.
* Mercer's condition — the kernel (Gram) matrix must be symmetric positive semi-definite ~~ Then it corresponds to an inner product in some space.
- It must be differentiable everywhere ~~ Not required.
- It must output only 0 or 1 ~~ No.
H: Valid kernel ⇔ PSD Gram matrix (Mercer).

Q: In an RBF-kernel SVM, a very large γ tends to:
* Overfit — the boundary becomes very wiggly around individual points ~~ Each point's influence is very local.
- Underfit — the boundary becomes linear ~~ That's small γ.
- Have no effect ~~ It strongly affects the boundary.
- Remove the support vectors ~~ No.
H: Big γ = local = overfit.

Q: In a soft-margin SVM, a very large C means:
* Misclassification is heavily penalised → narrow margin, risk of overfitting ~~ Behaves close to hard margin.
- The margin becomes very wide ~~ That's small C.
- No support vectors are used ~~ No.
- The kernel becomes linear ~~ C doesn't choose the kernel.
H: Large C = strict; small C = tolerant.

Q: Which problem is NOT linearly separable?
- AND ~~ Separable.
- OR ~~ Separable.
* XOR ~~ No single straight line separates (0,1),(1,0) from (0,0),(1,1).
- NOT ~~ Separable.
H: XOR needs a non-linear model (hidden layer or kernel).

Q: Which of these models is inherently linear (in its decision boundary)?
* Logistic regression without feature transformations ~~ The boundary b₀ + b·x = 0 is a hyperplane.
- Decision tree ~~ Piecewise, axis-aligned.
- kNN ~~ Arbitrary shape.

# knn | K-Nearest Neighbours
N: **kNN** is **lazy** (no training phase; it stores the data and computes at query time), **instance-based** and **non-parametric** (makes **no assumption** about the data distribution). Used for **classification AND regression** (and for **imputing missing values**).
N: Prediction: find the k nearest training points → classification = **most frequent class (majority vote)**; regression = mean of the neighbours' values.
N: Distances: **Euclidean** √Σ(xᵢ−yᵢ)², **Manhattan** Σ|xᵢ−yᵢ|, Minkowski (generalises both), **Hamming** for **categorical** data (count of mismatches), cosine for text.
N: **Small k → low bias, high variance** (overfits, noisy boundary). **Large k → higher bias, lower variance, smoother boundary**. Noisy data → **increase k**. Use odd k for binary problems to avoid ties.
N: kNN suffers from the **curse of dimensionality** (more irrelevant attributes can hurt accuracy) and needs **feature scaling**.
N: Choose k with cross-validation. Common rule of thumb: k ≈ √n.

H: kNN = lazy, non-parametric, classification + regression.

# kmeans | K-means & Other Clustering Methods
N: **K-means**: choose k centroids → assign each point to the **nearest centroid** → recompute centroids as cluster means → repeat until stable. Minimises the **within-cluster sum of squares (WCSS/inertia)**.
N: Choosing k: **Elbow method** (plot WCSS vs k, pick the bend) or silhouette score.
N: K-means weaknesses: **sensitive to outliers** and initialisation (different starts → different results; use **k-means++**), assumes convex/spherical clusters (can't find non-convex shapes), k must be given. It scales well to high-dimensional data.
N: **K-modes** = k-means for **categorical** data (uses modes and mismatch distance). **K-medoids** (PAM) uses actual points — more robust to outliers.

# som | Self-Organizing Maps (Kohonen)
N: **SOM (Kohonen map)** = an **unsupervised neural network** using **competitive learning** that maps high-dimensional data onto a low-dimensional (usually 2-D) grid while **preserving topology** (similar inputs → nearby nodes).
N: Algorithm: define the grid of nodes (neurons) → **initialise weight vectors randomly** → for each input, find the **Best Matching Unit (BMU)** = node with the closest weight → update **the BMU and its neighbours** towards the input → shrink the neighbourhood radius and learning rate over time.
N: Update rule: w(t+1) = w(t) + η(t)·h(BMU, i, t)·(x − w(t)). h is the neighbourhood function (often Gaussian).
N: Clustering with SOMs is in principle **similar to k-means** (prototypes move toward data), but neighbours are also updated, giving an ordered map. Used for visualisation, clustering and dimensionality reduction.
N: SOMs have **no backpropagation** and no target outputs.

# cnn | CNN Architectures
N: **Convolution layer**: filters slide over the input; output size = **(W − F + 2P)/S + 1** (W input, F filter, P padding, S stride). Parameters per layer = **(F × F × C_in + 1) × K** filters (shared weights → far fewer parameters than dense layers).
N: **Pooling** (max/average) downsamples (2 × 2, stride 2 halves width and height) → translation invariance, fewer computations. ReLU adds non-linearity. Fully connected layers + softmax classify.
N: **LeNet-5** (LeCun, 1998): handwritten digits, 32 × 32 input, conv–pool–conv–pool–FC.
N: **AlexNet** (2012, ImageNet winner): 5 conv + 3 FC, **ReLU, dropout, data augmentation, GPUs**; 227 × 227 input, first layer 96 filters 11 × 11 stride 4 → 55 × 55; ~60M parameters.
N: **VGG-16/19** (2014): only **3 × 3 convolutions** stacked deep; ~138M parameters (simple but heavy).
N: **GoogLeNet / Inception v1** (2014): **Inception modules** with parallel 1×1, 3×3, 5×5 convs + pooling; **1 × 1 convolutions** reduce depth (bottleneck); 22 layers, ~5M parameters; global average pooling.
N: **ResNet** (2015): **residual/skip connections** y = F(x) + x (addition) let very deep nets (50/101/152 layers) train — fixes degradation/vanishing gradients.
N: **Dropout** randomly drops neurons during training (regularisation). **Batch normalisation** normalises layer inputs → faster, stabler training. **Transfer learning**: reuse pretrained CNN features.

# rcnn | R-CNN, Fast R-CNN, Faster R-CNN & Mask R-CNN
N: **Object detection** = classify objects **and** localise them with bounding boxes. Quality is measured with **IoU** (intersection / union of boxes) and **mAP**.
N: **R-CNN** (Girshick, 2014): **selective search → ~2000 region proposals** → warp each region → CNN features (AlexNet) → **class-specific SVMs** + **bounding-box regression**. Accurate but **very slow** (a CNN pass per region), multi-stage training.

N: **Faster R-CNN** (2015): replaces selective search with a **Region Proposal Network (RPN)** that shares conv features and uses **anchor boxes** → nearly real-time, end-to-end.
N: **Mask R-CNN** (2017): Faster R-CNN + a **mask branch** for **instance segmentation**; uses **RoIAlign** instead of RoI pooling.
N: R-CNN family = **two-stage detectors** (propose, then classify). YOLO/SSD = one-stage. **Non-max suppression (NMS)** removes duplicate boxes.

# densenet | DenseNet

N: **Growth rate k** = number of feature maps each layer adds. The l-th layer has k₀ + k(l − 1) input channels; a block with L layers outputs k₀ + L·k channels.
N: **Transition layers** between blocks: BN → **1 × 1 conv** → **2 × 2 average pooling** (reduce size and channels; compression factor θ).
N: **DenseNet-B** uses 1 × 1 bottleneck convs; **DenseNet-BC** = bottleneck + compression. Common models: DenseNet-121/169/201.
N: Benefits: **feature reuse**, **alleviates vanishing gradients**, strong gradient flow, **fewer parameters** than ResNet for similar accuracy, regularising effect.
N: **ResNet adds** (x + F(x)); **DenseNet concatenates** [x₀, x₁, …, x_{l−1}].

# dqn | Reinforcement Learning & Deep-Q-Networks
N: **RL**: an agent takes actions in states, receives **rewards**, and aims to maximise the **discounted return** G = r₁ + γr₂ + γ²r₃ + … (0 ≤ γ < 1).
N: **Q(s, a)** = expected return from taking action a in state s and then acting optimally. **Bellman optimality**: Q*(s, a) = E[r + γ max_a' Q*(s', a')].
N: **Q-learning** (off-policy, model-free): Q(s, a) ← Q(s, a) + α [r + γ max_a' Q(s', a') − Q(s, a)] → converges to the **optimal policy** (π* = argmax Q). TD(0)/TD(1)/direct evaluation only estimate V(s) for a fixed policy. **SARSA** is on-policy.
N: **Deep Q-Network (DQN)** (DeepMind, Mnih et al. 2013/2015): a **CNN approximates Q(s, a)** from raw pixels (Atari games), outputting a Q-value for each action.
N: DQN stabilisers: **experience replay** (store transitions, sample random mini-batches → breaks correlations) and a **target network** (a periodically copied network that computes the targets r + γ max Q_target(s', a')).
N: Exploration: **ε-greedy** (random action with probability ε, decayed over time). Improvements: **Double DQN** (reduces overestimation), **Dueling DQN** (separate V(s) and advantage A(s, a)), prioritised replay.

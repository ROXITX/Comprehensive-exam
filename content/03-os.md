# basics | OS Basics, Types & Kernel
N: An **OS** is an interface between hardware and application programs, a **collection of programs that manages hardware resources**, and a **service provider** to programs. Services are accessed through **system calls**.
N: **Bootstrap program**: the initial program run at power-up (stored in ROM/firmware). It initialises CPU registers, device controllers and memory, then loads the OS kernel. On multi-OS machines the **boot loader** decides which OS to load.
N: **Kernel**: core of the OS, always in memory, first part loaded at boot. Modern kernels **can load modules at run time**. Types: **monolithic** (Linux), **microkernel** (QNX, Mach), **hybrid** (Windows NT, **macOS/OS X**).
N: **Trap/exception** = a **software-generated interrupt** caused by an error (divide by zero, invalid memory access) or by a user request (system call).
N: **Real-time OS** examples: **RTLinux, VxWorks, QNX, Windows CE**. **Palm OS is NOT real-time**. Hard RTOS: a task **must** meet its deadline, has **less jitter**; interrupt latency must be **minimal**.
N: **Multiprogramming**: several processes in memory at once → **increases CPU utilisation** (CPU time is used productively). **Uniprogramming/uniprocessing**: one process at a time. **Multiprocessing**: several CPUs run processes truly in parallel.
N: **Network OS** runs on the **server**. A **distributed OS** makes many machines look like one system.
N: **Transient OS code** comes and goes as needed, so it **changes** the size of the OS in memory. The OS sits in **low or high memory, depending on the location of the interrupt vector**.
N: The **command interpreter (shell)** gets and executes the next user-specified command. If a process fails, the OS writes the error information to a **log file**.

# process | Processes, PCB & Process States
N: **Process** = program in execution. Memory layout: **text (code), data (globals), heap (dynamic), stack** (function parameters, local variables, return addresses).
N: **States**: New → Ready → Running → Waiting (Blocked) → Ready … → Terminated. There is no "Old" state.
N: Time slice expires → **Running → Ready**. I/O completes → **Waiting → Ready**. I/O request → Running → Waiting. The only transition the process itself starts is **block** (by requesting I/O).
N: **PCB** (process control block) = **data structure** holding: process state, PC, CPU registers, scheduling info, memory-management info, accounting and I/O status. All PCBs are kept in the **process table**.
N: Each process has its own **address space, global variables, open files, pending alarms, signals and signal handlers**. Threads of a process share these.
N: **Queues**: job queue (all processes), **ready queue** (in memory, waiting for CPU), device/I/O queues. There is no "PCB queue".
N: **Schedulers**: **long-term** (job scheduler, chooses which processes enter the ready queue — controls the **degree of multiprogramming**); **short-term** (CPU scheduler, picks the next process to run — runs very often); **medium-term** (swapping out/in). Main difference between short- and long-term: **frequency of execution**.
N: **Dispatcher** gives the CPU to the process chosen by the short-term scheduler (context switch, switch to user mode, jump). **Dispatch latency** = time to stop one process and start another.
N: **Context switch** (also called process switch or task switch): save the old PCB, load the new one. The **TLB** need not be saved. The PCB does not contain "context switch time".
N: **fork()** returns **0 to the child** and the **child's PID (> 0) to the parent**. **wait()** makes the parent wait for a child to terminate. **exec()** loads a new program into the process. Child finishes but parent hasn't called wait → **zombie**. Parent dies first → **orphan**.
N: **Cascading termination**: when a parent terminates (normally or abnormally), all its children are terminated too.

# threads | Threads & Multithreading
N: **Thread** = basic unit of CPU utilisation: its own **thread ID, PC, register set and stack**; shares code, data, open files and signals with other threads of the process.
N: Benefits of multithreading: **responsiveness, resource sharing, economy** (cheaper to create/switch than processes), **scalability** on multicore.
N: **User-level threads**: managed by a thread library, **the kernel does not know them, so the kernel cannot schedule them**; fast switching, but one blocking call can block the whole process (many-to-one).
N: **Kernel-level threads**: managed and **scheduled by the kernel**; slower to create but can run in parallel.
N: Models: **Many-to-one** (many user threads → 1 kernel thread; no parallelism), **One-to-one** (Linux, Windows; more overhead), **Many-to-many** (flexible).
N: A **single thread of control** lets a process do **only one task at a time**.
N: **Multithreaded programs are more prone to deadlocks** (more locks, more interleavings).
N: Thread libraries: **POSIX Pthreads**, Windows threads, Java threads.

# ipc | Inter-Process Communication
N: **IPC** allows processes to **communicate and synchronise their actions**. Two models: **shared memory** and **message passing**. A process that can be affected by others is **cooperating**.
N: **Message passing** lets processes communicate **without sharing the same address space**. Operations: **send** and **receive**. Messages can be **fixed or variable size**. The connection is called a **communication link**.
N: **Direct communication**: name the other process explicitly; **a link is associated with exactly two processes**, and exactly one link exists per pair. **Indirect communication**: messages go through a **mailbox (port)**.
N: **Blocking (synchronous) send**: the sender waits until the message is received. **Non-blocking (asynchronous) send**: the sender sends and **resumes operation**.
N: Buffering: **Zero capacity** = **no buffering**; sender **blocks until the receiver receives** (rendezvous). **Bounded and unbounded capacity** = **automatic buffering**.
N: **RPC (Remote Procedure Call)**: IPC between processes on **different systems** using message-based communication.
N: Other IPC: **pipes** (ordinary/unnamed between related processes, named pipes/FIFOs), **sockets**, signals, message queues.

# sched | CPU Scheduling Concepts & Criteria
N: **CPU scheduling is the basis of multiprogrammed operating systems**; it aims to **increase CPU utilisation and throughput** and **decrease turnaround, waiting and response time**.
N: Process execution alternates **CPU bursts and I/O bursts**. **I/O-bound** program → **many short CPU bursts**; CPU-bound → a few long CPU bursts.
N: **Turnaround time** = completion − arrival (submission). **Waiting time** = total time in the **ready queue** = turnaround − burst. **Response time** = time from submission to the **first response**. **Throughput** = processes completed per unit time.
N: **Non-preemptive** scheduling happens only when a process switches **running → waiting** or **terminates**. **Preemptive** also happens on running → ready (timer) and waiting → ready.
N: **Preemptive scheduling** = making logically runnable processes temporarily suspended. It may cause **starvation** (as can SRTF and priority).
N: **Starvation (indefinite blocking)** of low-priority processes is solved by **aging** (gradually raising the priority of waiting processes).
N: **Priority inversion**: a high-priority task is indirectly preempted by a medium-priority task (because a low-priority task holds its lock). Fix: **priority inheritance**.
N: **Multilevel queue**: processes are classified into groups (foreground/background), each with its own queue; classification is permanent. **Multilevel feedback queue**: processes **can move between queues**.
N: **Round robin** is preemptive and uses a **time quantum**: a very large quantum → behaves like **FCFS**; a very small quantum → too many context switches.

# sync | Concurrency, Critical Section & Semaphores
N: **Race condition**: several processes access shared data concurrently and the result depends on the order of access.
N: **Critical-section solution requirements**: (1) **Mutual exclusion** — if one process is in its CS, no other is in theirs; (2) **Progress** — if no one is in the CS, the choice of who enters next can't be postponed indefinitely; (3) **Bounded waiting** — there's a limit on how many times others can enter **after a process has requested entry and before that request is granted**.
N: **Peterson's solution** (2 processes) uses **2 shared variables**: `flag[2]` and `turn`. Minimum shared variables for the CS problem = 2.
N: **Semaphore** = integer variable accessed only through two **atomic** operations: **wait (P, down)** and **signal (V, up)**. Binary semaphore (0/1) ≈ **mutex lock**. Counting semaphore for multiple instances. Classical semaphore value **cannot drop below zero**.
N: Counting semaphore arithmetic: final = initial − (number of P) + (number of V). e.g. 10 − 6 + 4 = 8.
N: Misuse: `signal(mutex) … CS … wait(mutex)` → **several processes in the CS** (no mutual exclusion). `wait(mutex) … CS … wait(mutex)` → **deadlock**.
N: **Monitor**: high-level construct that encapsulates **shared data, the procedures on it, and synchronisation** — only one process is active inside at a time. Waiting inside uses **condition variables** (`condition x; x.wait(); x.signal();`).
N: Synchronisation can be done in **hardware** (test-and-set, compare-and-swap, disabling interrupts) and **software** (Peterson, semaphores, monitors).
N: Classic problems: **producer–consumer (bounded buffer)**, **readers–writers**, **dining philosophers**.

# deadlock | Deadlocks
N: **Deadlock**: a set of processes where **each is blocked forever**, waiting for a resource held by another in the set.
N: **Four necessary conditions** (all must hold): **Mutual exclusion** (≥ 1 non-sharable resource), **Hold and wait** (hold ≥ 1 resource and wait for more), **No preemption**, **Circular wait**.
N: **Prevention** = make sure **at least one** condition cannot hold. Circular wait → **impose a linear ordering of resource types**. Hold & wait → request everything at once (**low resource utilisation**, possible starvation). No preemption → if a request can't be granted, **preempt all resources currently held**. Mutual exclusion is not required for sharable resources.
N: **Avoidance** needs a-priori info on the **maximum** need of each process. It dynamically examines the **resource-allocation state**. **Safe state** ⇔ there is a **safe sequence**. Unsafe ≠ deadlock (but may lead to it).
N: **Banker's algorithm**: Need = Max − Allocation. Find a process whose Need ≤ Available, let it finish, add its Allocation back to Available, repeat. It handles **multiple instances** but is **less efficient** than the resource-allocation-graph algorithm.
N: **Resource-allocation graph** (and **wait-for graph**) avoidance/detection works only for **single-instance** resources. In a wait-for graph, edge **Pi → Pj means Pi waits for Pj** to release a resource; **a cycle means deadlock** (single instance).
N: Detection frequency: if deadlocks occur **frequently**, run detection **frequently**. Recovery: abort processes or preempt resources.
N: **Minimum resources to guarantee no deadlock**: n processes each needing up to k units → **n(k − 1) + 1**.
N: Requests and releases of resources are **system calls**. A **reusable resource** can be used by one process at a time and is not depleted by use.

H: Deadlock = everyone stuck forever.

# memory | Memory Management: Allocation, Paging & Segmentation
N: **Logical (virtual) address** generated by the CPU; **physical address** seen by memory. **MMU** maps them. Protection: every CPU address is checked against the **relocation (base) and limit registers**.
N: **Contiguous allocation**: First fit (first hole big enough), **Best fit** (smallest adequate hole), **Worst fit** (largest hole). First and best fit are generally better than worst fit.
N: **External fragmentation**: enough total free memory, but not contiguous → fix with **compaction** or paging. **Internal fragmentation**: unused space inside an allocated block (paging has it in the last page).
N: **Paging**: logical memory → fixed-size **pages**; physical → **frames** of the same size. No external fragmentation. Address = page number + offset. The OS keeps a **frame table** (which frames are free/allocated).
N: Page table size = number of pages × entry size. 32-bit address, 4 KB pages → 2²⁰ pages; with 4-byte entries → 4 MB page table.
N: **Segmentation**: variable-size logical units (code, stack, data); address = (segment, offset); has external fragmentation.
N: **Dynamic loading**: routines are loaded only when called; **user programs can implement it without special OS/hardware support**. **Dynamic linking** needs OS support.
N: **Swapping**: move a process out to disk and back. **Never swap a process with pending I/O** into its own memory (or do I/O only into OS buffers).
N: **Device drivers** present a uniform device-access interface to the I/O subsystem.

# vmem | Virtual Memory & Page Replacement
N: **Demand paging**: load a page only when it is referenced. A missing page → **page fault** → OS loads it from disk.
N: **Effective access time** = (1 − p) × memory access + p × page-fault service time. Even p = 0.001 slows memory a lot (200 ns → ~8.2 µs with 8 ms faults).
N: Page replacement: **FIFO** (oldest page out; suffers **Belady's anomaly** — more frames can mean MORE faults), **Optimal/OPT** (replace the page not used for the longest time in future — lowest faults, not implementable), **LRU** (least recently used — good approximation; stack algorithm, no Belady's anomaly).
N: Classic string 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1 with 3 frames → **FIFO 15, LRU 12, OPT 9** faults.
N: Belady string 1 2 3 4 1 2 5 1 2 3 4 5 → FIFO **9 faults with 3 frames, 10 with 4 frames**.
N: **Thrashing**: a process spends more time paging than executing (too few frames). Fix: working-set model, page-fault-frequency control, lower the degree of multiprogramming.
N: **Working set** = pages referenced in the last Δ references. If the sum of working sets exceeds the available frames, **the OS suspends (swaps out) a process**.
N: **Copy-on-write**: after fork, parent and child share pages until one writes.

- Too many directories ~~ There is just one.
* Naming collisions and no grouping — all users share one namespace ~~ Every file needs a unique name.
- Cycles ~~ Can't happen.
- Slow disk access ~~ Unrelated.
H: Single-level → name clashes.

Q: The operating system _______ the links when traversing directory trees, to preserve the acyclic structure of the system.
- deletes ~~ Links are kept.
- considers ~~ Following them could create cycles.
* ignores ~~ Links are skipped during traversal.
- none ~~ Ignores is correct.
H: Traversal ignores links → stays acyclic.

Q: Which file allocation method suffers from external fragmentation?
* Contiguous allocation ~~ Files need runs of free blocks.
- Linked allocation ~~ Any free block can be used.
- Indexed allocation ~~ Any free block can be used.
- None ~~ Contiguous does.
H: Contiguous → external fragmentation.

Q: Which allocation method does NOT support efficient direct (random) access?
- Contiguous ~~ Block address = start + i.
* Linked allocation ~~ You must follow pointers from the start.
- Indexed ~~ The index block gives direct pointers.
- All support it equally ~~ Linked does not.
H: Linked = sequential only.

Q: Unix inodes are an example of:
- Contiguous allocation ~~ No.
- Linked allocation ~~ No.
* Indexed allocation (with direct and indirect pointers) ~~ Combined scheme.
- FAT ~~ A linked variant.
H: inode = indexed.

Q: Disk queue 98, 183, 37, 122, 14, 124, 65, 67 with the head at 53. Total head movement with FCFS is:
- 236 ~~ That's SSTF.
* 640 ~~ 45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = 640.
- 208 ~~ Wrong.
- 382 ~~ Wrong.
H: FCFS: sum of jumps in arrival order.

Q: Same queue (98, 183, 37, 122, 14, 124, 65, 67; head 53) with SSTF. Total head movement?
* 236 ~~ 53→65→67→37→14→98→122→124→183 = 12+2+30+23+84+24+2+59 = 236.
- 640 ~~ That's FCFS.
- 208 ~~ Recount.
- 299 ~~ Recount.
H: SSTF: always go to the nearest request.

Q: Which disk scheduling algorithm can cause starvation of far-away requests?
- FCFS ~~ Fair by order.
* SSTF ~~ Nearby requests keep getting served first.
- SCAN ~~ Sweeps across the whole disk.
- C-SCAN ~~ Uniform wait times.
H: SSTF → starvation.

Q: The SCAN disk scheduling algorithm is also known as:
* Elevator algorithm ~~ The head sweeps back and forth like a lift.
- Shortest seek ~~ That's SSTF.
- Circular queue ~~ No.
- Round robin ~~ No.
H: SCAN = elevator.

Q: Disk access time consists of:
* Seek time + rotational latency + transfer time ~~ Move the arm, wait for the sector, read it.
- Only seek time ~~ Incomplete.
- CPU time + I/O time ~~ No.
- Page fault time ~~ No.
H: Seek + rotate + transfer.

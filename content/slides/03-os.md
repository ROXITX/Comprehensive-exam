# basics
S: 🖥️ What is an operating system?
> The OS is the **manager** of the computer: it sits between your apps and the hardware.
> - Shares out the CPU, memory and devices
> - Gives programs services through **system calls**
> 💡 Like a hotel manager: guests (apps) ask, the manager handles the rooms (hardware).
S: Starting the computer
> - **Bootstrap program** (in ROM): first program at power-on; sets up the hardware and loads the kernel.
> - **Boot loader**: picks which OS to load (e.g. GRUB) on multi-OS machines.
> - **Kernel**: the core of the OS, always in memory; modules can be loaded while running.
S: Types of kernels and OS
> - **Monolithic** (Linux), **Microkernel** (QNX), **Hybrid** (Windows, macOS).
> - **Real-time OS** (VxWorks, RTLinux, QNX, Windows CE) must meet **deadlines**; hard RTOS has less jitter.
> - **Network OS** runs on the server.
S: Multiprogramming
> Keep **several programs in memory**. When one waits for I/O, the CPU runs another → **better CPU utilisation**.
> - **Time-sharing**: switch so quickly that each user feels they have the machine.
> - **Multiprocessing**: several CPUs truly in parallel.
> A **trap** is a software interrupt (error or system call).

# process
S: 🏃 Process = program in action
> A program on disk is just a file. When it runs, it becomes a **process** with its own:
> code, data, **heap** (malloc), **stack** (function calls, locals, return addresses).
S: Process states
> **New → Ready → Running → Waiting → Ready … → Terminated**
> - Time slice over → back to **Ready**
> - Asks for I/O → **Waiting**
> - I/O done → **Ready** (not straight to running!)
S: PCB — the process's ID card
> The **Process Control Block** stores: state, program counter, registers, memory info, open files, scheduling info.
> All PCBs live in the **process table**. Switching CPU between processes = **context switch**.
S: Schedulers
> - **Long-term**: which jobs enter memory (controls the degree of multiprogramming)
> - **Short-term (CPU scheduler)**: which ready process runs next — runs very often
> - **Medium-term**: swaps processes out/in
> The **dispatcher** actually hands the CPU over.
S: fork, wait, exec
> - **fork()** → creates a child copy; returns **0 to the child**, the child's PID to the parent.
> - n forks → **2ⁿ** processes.
> - **wait()** → parent waits for the child. **exec()** → load a new program.
> - Child finished but not waited for → **zombie**; parent died → **orphan**.

# threads
S: 🧵 Threads
> A thread is a **lightweight process** inside a process.
> Threads **share** code, data and open files, but each has its own **stack, registers and program counter**.
> 💡 One kitchen (process), several cooks (threads).
S: Why use threads?
> - **Responsiveness** (UI keeps working)
> - **Resource sharing**
> - **Economy** (cheaper than new processes)
> - **Scalability** on multi-core CPUs
S: User vs kernel threads
> - **User-level**: managed by a library — the **kernel can't see or schedule them**.
> - **Kernel-level**: scheduled by the OS.
> Models: many-to-one (one block blocks all), **one-to-one** (Linux, Windows), many-to-many.

# ipc
S: 📨 Inter-Process Communication
> Processes need to **talk and coordinate**. Two ways:
> - **Shared memory**: share a region of memory (fast).
> - **Message passing**: **send** and **receive** messages (no shared memory needed).
S: Direct vs indirect
> - **Direct**: name the other process; a link joins **exactly two** processes.
> - **Indirect**: messages go through a **mailbox (port)**.
> - **Blocking** send waits; **non-blocking** send continues immediately.
S: Buffering
> - **Zero capacity** → no buffering, the sender waits for the receiver.
> - **Bounded / unbounded capacity** → **automatic buffering**.
> - **RPC**: calling a procedure on **another machine**. Also pipes and sockets.

# sched
S: ⏳ CPU scheduling — who runs next?
> Goal: keep the CPU busy and users happy.
> - Maximise **CPU utilisation & throughput**
> - Minimise **turnaround, waiting & response time**
S: The time words
> - **Turnaround** = completion − arrival
> - **Waiting** = time in the **ready queue** = turnaround − burst
> - **Response** = time until the **first** response
> - **Throughput** = jobs finished per unit time
S: The algorithms
> - **FCFS**: first come first served (convoy effect)
> - **SJF**: shortest job first — **lowest average wait**; hard to know burst lengths
> - **SRTF**: preemptive SJF
> - **Priority**: highest priority first — low ones may **starve** → fix with **aging**
> - **Round Robin**: each gets a **time quantum** (preemptive); a huge quantum → FCFS
> - **Multilevel (feedback) queue**: groups of queues (feedback lets processes move)
S: Preemptive vs not
> **Non-preemptive**: the CPU is given up only when the process waits or ends.
> **Preemptive**: the OS can take the CPU away (timer).
> **Priority inversion**: a low task holding a lock blocks a high task → fix with priority inheritance.

# schedcalc
S: 🧮 Solving scheduling sums
> Step 1: draw a **Gantt chart** (a timeline of who runs when).
> Step 2: for each process, Turnaround = finish − arrival, Waiting = turnaround − burst.
> Step 3: average them.
S: Worked FCFS example
> P1 = 24, P2 = 3, P3 = 3 (all at time 0):
> - Gantt: P1 0–24, P2 24–27, P3 27–30
> - Waits: 0, 24, 27 → **average 17**
> - Run short jobs first (P2, P3, P1) → average **3**
S: Worked SJF example
> P1 = 6, P2 = 8, P3 = 7, P4 = 3:
> - Order P4, P1, P3, P2
> - Waits: P4 0, P1 3, P3 9, P2 16 → **average 7**
S: Worked Round Robin (q = 4)
> P1 = 24, P2 = 3, P3 = 3:
> - P1 0–4, P2 4–7, P3 7–10, P1 10–30
> - Waits: P1 6, P2 4, P3 7 → **average 5.66**

# sync
S: 🚦 Why synchronisation?
> When processes share data, the result can depend on who goes first — a **race condition**.
> The code touching shared data is the **critical section (CS)**.
S: Three rules for a correct solution
> - **Mutual exclusion**: only one in the CS at a time
> - **Progress**: if the CS is free, someone who wants in must get in
> - **Bounded waiting**: nobody waits forever
> **Peterson's solution** uses 2 shared variables: flag[] and turn.
S: Semaphores
> An integer changed only by two **atomic** operations:
> - **wait (P)**: decrease; block if not available
> - **signal (V)**: increase; wake someone
> Binary semaphore ≈ mutex lock. Counting: final = start − P's + V's (10 − 6 + 4 = 8).
S: Common mistakes
> - signal → CS → wait: **many** processes get into the CS.
> - wait → CS → wait: **deadlock**.
> **Monitors** bundle the shared data + procedures + sync; you wait inside them with **condition variables**.

# deadlock
S: 🔒 What is deadlock?
> A group of processes where each waits forever for something another one holds.
> 💡 Four cars at a crossroads, each waiting for the next to move.
S: Four conditions (all needed)
> - **Mutual exclusion** (a non-sharable resource)
> - **Hold and wait**
> - **No preemption**
> - **Circular wait**
> Break any **one** → no deadlock (prevention). E.g. number the resources and request in order → no circular wait.
S: Avoidance — Banker's algorithm
> Needs each process's **maximum** need in advance.
> Need = Max − Allocation. Find a process whose Need ≤ Available, let it finish, take back its resources, repeat.
> If everyone can finish → **safe state** (there is a **safe sequence**).
S: Detection & numbers
> - Wait-for graph (single instances): a **cycle = deadlock**.
> - Minimum resources so n processes each needing k never deadlock: **n(k − 1) + 1**.
> - Recover by aborting processes or preempting resources.

# memory
S: 🧱 Memory management
> The OS gives each process its own part of RAM and protects it with **base and limit registers** — every address is checked.
S: Placing processes
> - **First fit**: first hole that fits
> - **Best fit**: smallest hole that fits
> - **Worst fit**: biggest hole
> **External fragmentation**: free space is broken into small gaps → fix with compaction or paging.
S: Paging
> Split programs into **pages** and RAM into **frames** of the same size. Any page can go into any frame → no external fragmentation (a little **internal** waste in the last page).
> Address = page number + offset. The OS also keeps a **frame table**.
S: Segmentation & loading
> - **Segmentation**: variable-size logical parts (code, stack, data).
> - **Dynamic loading**: load a routine only when called — the program can do it itself.
> - Never swap a process that has pending I/O.

# vmem
S: 🪄 Virtual memory & demand paging
> Load a page **only when it is needed**. A missing page → **page fault** → load it from disk.
> Even rare page faults are very slow, because disks are slow.
S: Page replacement — who gets kicked out?
> - **FIFO**: oldest page out (can suffer **Belady's anomaly**: more frames → more faults!)
> - **LRU**: least recently used out
> - **Optimal**: the page not needed for the longest time — best, but needs to know the future
> Classic string, 3 frames: FIFO **15**, LRU **12**, OPT **9**.
S: Thrashing
> Too many processes, too few frames → constant paging, CPU nearly idle.
> Fix: give processes their **working set**, or **suspend** a process when the total demand is too high.

# files
S: 📁 File systems
> - **Directory**: keeps information about files.
> - **Open-file table**: tracks files currently open.
> - Directory types: single-level (all in one), two-level, tree, acyclic graph (the OS ignores links during traversal).
S: Storing files on disk
> - **Contiguous**: fast, but external fragmentation
> - **Linked**: no fragmentation, but slow random access
> - **Indexed**: an index block lists the blocks (Unix inodes)
S: Disk scheduling
> - **FCFS**: in request order
> - **SSTF**: nearest request first (may starve far ones)
> - **SCAN** (elevator), C-SCAN, LOOK
> Queue 98, 183, 37, 122, 14, 124, 65, 67 with head at 53 → FCFS **640**, SSTF **236**.

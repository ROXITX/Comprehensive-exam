# switching
S: 🔀 Switching — how data finds a path
> - **Circuit switching**: reserve a dedicated path first, then talk (old telephones). Connection-oriented; best for constant, long traffic.
> - **Packet switching**: chop data into packets; each is **stored and forwarded** hop by hop. Best for bursty traffic.
S: Two flavours of packet switching
> - **Datagram**: each packet finds its own way (connectionless; may arrive out of order).
> - **Virtual circuit**: set up a route first; **all packets follow it** (uses global + local addresses). If a router on it fails, the circuit dies.
S: Frame Relay & ATM
> - **Frame Relay**: fast virtual-circuit WAN with **no error/flow control**.
> - **ATM (cell switching)**: tiny fixed **53-byte cells** (5 header + 48 data), identified by VPI/VCI.
> - AAL1 constant bit rate; **AAL3 connection-oriented** data; AAL4 connectionless; AAL5 simple data.
> 💡 A crossbar switch with n inputs and m outputs needs n × m crosspoints (30 × 30 = 900).

# models
S: 🧱 OSI — 7 layers
> **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way:
> Physical, Data link, Network, Transport, Session, Presentation, Application.
> 💡 Each layer does one job and hands the data to the next.
S: What each layer does
> - Physical: bits & **speed**
> - Data link: frames, MAC, **flow/error control**
> - Network: IP addresses, **routing**
> - Transport: ports, process-to-process, combining data from many apps
> - Session: dialogue control
> - Presentation: **encryption**, compression
> - Application: HTTP, FTP, SMTP
S: TCP/IP model
> Only 4 layers: Link, Internet, Transport, Application — **no Session or Presentation layer**.
> IPv4 header = **20 bytes** + options (up to 60 bytes).

# topology
S: 🕸️ Network shapes
> - **Bus**: one cable (classic Ethernet)
> - **Star**: everyone to a central hub (hub fails → all fail)
> - **Ring**: each connects to two neighbours
> - **Mesh**: everyone to everyone → most reliable. n devices → **n(n−1)/2 cables**, **n − 1 ports** each (10 → 45 and 9)
S: Devices
> - **Hub** (layer 1): repeats to everyone
> - **Switch** (layer 2): sends only to the right port (MAC)
> - **Router** (layer 3): connects **different networks**
> - **Gateway**: connects networks using **different protocols**
S: Signals & speeds
> - **Bandwidth** = highest − lowest frequency (1 kHz to 40 MHz → 39.999 MHz)
> - Half duplex = walkie-talkie; full duplex = phone; simplex = keyboard
> - MAC = 48 bits; IPv4 = 32 bits; IPv6 = 128 bits
> - LAN covers a few km; the Internet is a WAN

# errors
S: 🩺 Errors in transmission
> - **Single-bit error**: 1 bit flips
> - **Burst error**: 2 or more bits flip
> **Hamming distance** = number of differing bits (10101 vs 11110 → 3).
S: Detecting errors
> - **Parity**: catches an **odd** number of flipped bits only
> - **Checksum**: uses **1's complement** arithmetic
> - **CRC**: divide using **XOR (mod-2)**; the remainder is sent along (1 + 1 = 0 in mod-2)
S: Correcting errors
> **Hamming code**: add r parity bits where 2^r ≥ m + r + 1 (4 data bits → 3 parity bits).
> The syndrome (e.g. 0101 = 5) gives the **position of the bad bit**.
> To correct t errors you need minimum distance **2t + 1**.

# ip
S: 🏠 IP addresses
> An IPv4 address is 4 numbers (32 bits): 192.168.1.10.
> Classes by first number: **A 1–126, B 128–191, C 192–223, D 224–239 (multicast)**.
> Private ranges: 10.x, 172.16–31.x, 192.168.x. A host on the Internet needs a **public** address.
S: Subnetting in one minute
> /n = number of network bits. Network address = IP AND mask.
> - /24 → 254 hosts, /26 → 62, /27 → 30 (2^host bits − 2)
> - 12.12.12.12/20 → network **12.12.0.0**
S: Helper protocols
> - **ARP**: IP → MAC address
> - **ICMP**: errors & ping
> - **DHCP**: hands out IP addresses automatically
> - **IPv6**: 128-bit; traffic class ≈ ToS, hop limit ≈ TTL

# routing
S: 🧭 Routing
> Routers decide the next hop using a **routing table**.
> - **Static**: typed in by an admin
> - **Dynamic**: learned automatically by protocols
S: The three families
> - **Distance vector** (RIP): tell your neighbours your table; max 15 hops; count-to-infinity problem.
> - **Link state** (OSPF): everyone learns the full map and runs **Dijkstra**; cost can be based on throughput.
> - **Path vector** (BGP): **between** autonomous systems.
> Intra-domain: RIP, OSPF. Inter-domain: BGP.

# transport
S: 🚚 TCP vs UDP
> - **TCP**: connection-oriented, **reliable**, ordered, flow + error + congestion control. 3-way handshake: SYN → SYN-ACK → ACK.
> - **UDP**: connectionless, fast, no guarantees (DNS, video calls).
S: Sockets & ports
> **Socket = IP address + port number.**
> Server: socket → bind → listen → accept. Client: socket → **connect**.
> Ports: 20/21 FTP, 22 SSH, 23 Telnet, 25 SMTP, 53 DNS, 80 HTTP, 110 POP3, 143 IMAP, 443 HTTPS.
S: Sliding windows
> Send window = **min(receiver window, congestion window)** (5 KB and 2 KB → 2 KB).
> ACKs can be cumulative → fewer ACKs than frames.
> Go-Back-N window ≤ 2ᵐ − 1; Selective Repeat ≤ 2ᵐ⁻¹.

# congestion
S: 🚦 Flow vs congestion control
> - **Flow control** protects the **receiver**.
> - **Congestion control** protects the **network**.
S: Fixing congestion
> - **Back pressure**: node-to-node slow-down
> - **Choke packet**: the congested router tells the **source** directly
> - **Discarding policy**: drop less important packets without harming the transmission
> - Leaky bucket (smooth output) vs token bucket (allows bursts)
S: TCP's approach
> - **Slow start**: window doubles each round trip until the threshold
> - Then **+1** each round trip (congestion avoidance)
> - On timeout: threshold = half, window back to 1
> This pattern is **AIMD** (additive increase, multiplicative decrease).

# app
S: 🌐 Application protocols
> - **HTTP/HTTPS**: web
> - **FTP**: files — 1 control connection + **1 data connection per file** (10 files → 11)
> - **SMTP**: send mail; **POP3/IMAP**: fetch mail
> - **DNS**: names → IP addresses
> - **SNMP**: network management
> ICMP, IGMP and ARP are **not** application-layer.

# crypto
S: 🔐 Two kinds of cryptography
> - **Symmetric**: the **same key** locks and unlocks (AES, DES). Fast, but sharing the key is hard.
> - **Asymmetric (public key)**: a **public key** encrypts and a **private key** decrypts (RSA). Slower, but **easier key management**.
S: AES & DES numbers
> - **AES**: 128-bit block; keys 128/192/256 → **10/12/14 rounds**
> - **DES**: 64-bit block, 56-bit key, 16 rounds
> - S-AES (teaching version): 16-bit key
S: RSA in 4 steps
> 1. n = p × q
> 2. φ = (p − 1)(q − 1)
> 3. pick e; find d with e·d ≡ 1 (mod φ)
> 4. Encrypt C = Mᵉ mod n; decrypt M = Cᵈ mod n
> p = 3, q = 11, e = 7 → **d = 3**.
S: Diffie–Hellman & attacks
> Diffie–Hellman lets two people agree on a shared key over an open channel (q = 23, α = 5, a = 6, b = 15 → key **2**).
> Attacks: brute force, dictionary, **rainbow tables** (pre-computed hashes — stopped by salting), social engineering, **man-in-the-middle**.
> Caesar cipher: shift by 3 (HQFUBSWHG → ENCRYPTED).

# dsig
S: ✍️ Digital signatures
> - **Sign** with your **private** key; others **verify** with your **public** key.
> - Gives **authentication, integrity, non-repudiation** — but **not confidentiality**.
> 💡 Anarkali signs → Salim verifies with **Anarkali's public key**.
S: MAC vs hash
> - **Hash/MDC**: detects changes (integrity)
> - **MAC**: keyed hash — also proves **who** sent it (data origin)
S: Distributing public keys
> Public announcement → directory → **public-key authority** (a trusted third party) → **certificates** (most secure, signed by a CA, X.509).
> A **KDC** creates a one-time **session key** for each session.

# auth
S: 🪪 Authentication
> Proving **who you are**. Three factors:
> - Something you **know** (password)
> - Something you **have** (smart card, token)
> - Something you **are** (fingerprint)
> Password + token = **two-factor**; a fingerprint alone = **single-factor**.
S: Kerberos
> A ticket system using a trusted third party:
> 1. Log in to the **Authentication Server** → get a ticket-granting ticket
> 2. Ask the **Ticket-Granting Server** for a service ticket
> 3. Show the ticket to the service
> It uses symmetric keys and timestamps. **CHAP** = Challenge Handshake Authentication Protocol.

# firewall
S: 🧱 Firewalls
> A firewall checks incoming/outgoing traffic against **rules**.
> - Packet filter (IPs, ports)
> - **Stateful/dynamic** filter (tracks TCP & UDP sessions)
> - Application gateway / proxy (understands the application)
> A layer-4 firewall **can't block a specific user** — it can't see users.
S: Security protocols
> - **HTTPS** = HTTP + TLS (secure web)
> - **SSL/TLS**: confidentiality + integrity
> - **SSH**: secure remote login
> - **IPSec**: transport or tunnel mode; **AH** = authentication, **ESP** = encryption
> - **PGP**: secure email

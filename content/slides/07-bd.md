# arch
S: 🐘 What is Big Data?
> Data too big or fast for one computer. The **3 Vs**:
> - **Volume** (huge size)
> - **Velocity** (arrives fast)
> - **Variety** (tables, JSON, text, images)
S: The typical analytics pipeline
> Sources → **ingest** (Kafka, Flume, Sqoop) → **store** (HDFS / data lake / warehouse) → **process** (Hadoop, **Spark**) → **analyse** (OLAP) → **BI dashboards** (Tableau, Power BI).
S: Key words
> - **Data lake**: raw data, schema-on-read
> - **Data warehouse**: clean, structured data
> - **OLAP** = Online Analytical Processing (roll-up, drill-down, slice, dice)
> - **Columnar databases** → faster analytical queries

# hadoop
S: 🗂️ Hadoop
> Open-source framework to **store and process** huge data on many cheap machines. Strengths: **fault tolerance** and **scalability** (batch, not real-time).
S: HDFS — the storage
> - Files are cut into **128 MB blocks**, each copied **3 times**
> - **NameNode**: keeps the **metadata** (which blocks are where)
> - **DataNodes**: store the actual blocks and send heartbeats
> - Secondary NameNode: checkpoints only (not a backup)
S: YARN & friends
> - **YARN**: manages and schedules cluster resources
> - **Hive**: SQL-like queries · **Pig**: scripts · **HBase**: NoSQL store
> - **Sqoop**: database ↔ HDFS · **Flume**: logs · **Oozie**: workflows · **ZooKeeper**: coordination

# mapreduce
S: 🗺️ MapReduce in plain words
> Split a big job into many small ones:
> - **Map**: turn each input piece into **(key, value)** pairs
> - **Shuffle & sort**: group pairs by key
> - **Reduce**: combine the values for each key
S: Word count example
> Input: "big data big"
> - Map → (big, 1), (data, 1), (big, 1)
> - Reduce → (big, 2), (data, 1)
> 💡 A **combiner** pre-adds counts on each machine to save network traffic.
S: Who does what
> - **Mapper** maps input pairs → intermediate pairs
> - A **map task** processes one chunk (input split)
> - **Reduce** consolidates all map results
> - The **partitioner** decides which reducer gets each key
> Can be written in Java (and Python via Streaming).

# spark
S: ⚡ Apache Spark
> A fast cluster engine that keeps data **in memory** → often 10–100× faster than MapReduce for repeated work. It is the **processing and analytics** part of the architecture.
S: SparkContext
> **SparkContext** is the entry point, created in the **driver program**. It talks to the cluster manager (Standalone, YARN, Kubernetes), which gives it **executors**.
> - `spark.default.parallelism` → default parallelism
> - `setCheckpointDir()` → where checkpoints are stored
> In Spark 2+, **SparkSession** wraps it.
S: How a job runs
> An action → a **DAG** of stages (split at shuffles) → tasks.
> The optimiser pipelines narrow steps and picks the best plan.
> **Data locality**: run tasks where the data already is.

# rdd
S: 🧱 RDD — Resilient Distributed Dataset
> Spark's basic data: a collection split across machines.
> - **Immutable** (never changed in place)
> - **Resilient**: lost pieces are rebuilt from the **lineage** (the recipe of steps)
> - Kept **in memory**
S: Creating RDDs
> 1. `sc.parallelize([1, 2, 3])`
> 2. `sc.textFile("hdfs://…")`
> 3. Transforming an existing RDD
S: Transformations vs actions
> - **Transformations** (lazy, return a new RDD): map, filter, flatMap, **reduceByKey**, join
> - **Actions** (run the job): **count**, collect, take, saveAsTextFile
> **Lazy**: nothing runs until an action is called.
S: Shuffles & caching
> - reduceByKey / groupByKey / join → **shuffle** data across machines
> - map / filter → no shuffle (narrow)
> - **cache()** an RDD you use **many times**

# assoc
S: 🛒 Association rules — market baskets
> Find items bought together: {Diapers} → {Beer}.
> - **Support count**: how many baskets contain the itemset
> - **Support** = count / total baskets
S: Confidence & lift
> - **Confidence(A → B)** = support(A and B) / support(A)
> - **Lift** = confidence / support(B) — above 1 means a real link
> 5 baskets: {Diaper} in 4, {Diaper, Beer} in 3 → confidence **0.75**.
S: Apriori
> A **frequent itemset** meets the minimum support.
> **Apriori rule**: every subset of a frequent itemset is frequent → prune anything with an infrequent subset.
> Speed-ups: hashing, transaction reduction, partitioning, sampling. **FP-Growth** skips candidate generation.

# sequence
S: ⏩ Sequence rules
> Like association rules, but **order matters**: "laptop → then laptop bag → then mouse".
> **Sequence support** = share of customers whose history contains the pattern in that order.
> Algorithms: **GSP** (Apriori-style), SPADE, **PrefixSpan**.
> Uses: shopping histories, website clicks, DNA.

# graph
S: 🕸️ Graph analytics
> Data as **nodes** and **edges** (friends, links, transactions).
> - Shortest paths
> - **PageRank**: important pages are linked from important pages (damping 0.85)
> - **Community detection**: find tight groups
> - Connected components, triangle counting
> Tools: Spark **GraphX**, Pregel (think like a vertex), **Neo4j** (Cypher).

# sna
S: 👥 Social network metrics
> - **Degree centrality**: number of friends (normalised: degree / (n − 1))
> - **Betweenness**: sits on many shortest paths → a **broker/bridge**
> - **Closeness**: can reach everyone quickly
> - **Eigenvector**: friends with important people
S: Whole-network measures
> - **Density** = edges / possible edges (5 nodes, 4 edges → 0.4)
> - **Clustering coefficient**: are my friends friends with each other?
> - **Diameter**: the longest shortest path
> - **Homophily**: similar people connect
